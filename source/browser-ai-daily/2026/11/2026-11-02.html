今天最值得看

1. MoGe-3 WebGPU：新开源端侧 3D 视觉推理，修正 Firefox/Metal Shader 兼容性（24 小时内提交）

发生了什么：10 月 30 日创建的 xjodoin/moge3-webgpu 将 MoGe-3 ViT-L 的单图三维重建移植到浏览器，使用 ONNX Runtime WebGPU 执行稠密部分，以专用 WGSL Kernel 处理稀疏三维细化；这是第三方非官方移植，不是 Microsoft 官方新版本。11 月 1 日 23:35 UTC 的 提交修复 Firefox 158 + Metal 上 ONNX Runtime 生成的索引数组类型别名冲突；11 月 2 日 00:06 UTC 的 提交引入有损紧凑权重下载与可无损恢复原始 FP32 字节的升级流程。

验证边界：作者给出 Apple M4 Pro 上 Firefox 158 的 18 组兼容性运行及 Chrome 156 的 54 组与 CUDA 参考的对照测试；没有独立复现。README 报告单一 Fast 模式模型约 1.24 GB 起始下载、需要数 GB 内存，WebGPU Subgroup 路径在 Chrome 156 上把 Fast 三轮细化的热运行耗时从 1.531 s 降至 1.272 s（作者 Benchmark），不能推广到手机。为什么值得看：同时覆盖跨浏览器 Shader 兼容、模型权重传输、Kernel 实测及数值验证。工程启发：把 Chrome/Firefox 的 WGSL 编译差异、模型原始哈希、推理误差及下载缓存变为同一份可重放实验记录；针对不同 GPU 能力选择 Kernel，而非假设通用性能。

2. Browser Harness：六个真实网站 Skill 经独立 Agent 重放后正式合并（24 小时内）

发生了什么：browser-use/browser-harness PR #961 于 11 月 1 日 20:09 UTC 合并，增加 Discogs、Google Trends、Wikipedia、Ticketmaster、Zoopla、Chess.com 六个站点 Skill。作者在真实云端浏览器探索公开页面，再由另一个独立 Agent 在新的未登录浏览器中原样执行每段代码；验证过程发现排序不稳定、页面元信息混入、抓取口径不准确等问题，并对部分内容进行了修正。

为什么值得看：这不是让 Agent“自行声称成功”，而是把已执行方法提升为可复验的领域资产。Skill 仅作为文档存在、需要显式启用 BH_DOMAIN_SKILLS=1，并规定尊重 robots.txt、不规避站点限制。闭环进度：Observe（真实网站）→ Learn 候选（Skill）→ 独立 Verify → 修订 → Merge；尚无持续线上故障反馈及 Canary。工程启发：浏览器工程的 Skill Registry 可以采用“原始操作记录、独立无登录复演、反例修正、版本化晋级”的门禁，对 WPT 自生成用例也适用。以上为 PR 作者提供的验证记录，未独立执行测试。

3. BrowserBear：本机 Chrome Profile + Native Host + CDP 的早期新项目（7 日内首次出现；24 小时内改进）

发生了什么：10 月 29 日创建的 mikecann/browserbear 使用 Chrome Extension、Native Messaging Host、本地 Unix Socket 与 chrome.debugger，让 Coding Agent 在指定的真实 Chrome Profile 与标签页工作，而不是每次启动全新隔离浏览器。其 Snapshot 支持增量差异，用户可通过 handoff 接管任务。11 月 1 日的 提交补上输入框替换后的回读校验，避免受控输入组件偷偷恢复旧文本；另一次 提交处理第三方扩展 iframe 与 SVG 交错时的调试失败。

为什么值得看：它针对 Agent 真实使用中容易出错的 Profile 识别、标签所有权、自动输入及用户接管，提供了可读的实现，而不是只有产品宣发。成熟度：作者明确称为早期项目，仅 macOS + Chrome 156，暂无公开独立成功率测试；扩展对真实 Profile 和登录态的访问必须经过严谨授权审查。工程启发：将动作前的 Snapshot、动作后的字段回读和接管状态统一成 Browser Runtime 的可信操作回执。

4. Vercel Labs agent-desktop 1.0：结构化桌面访问补齐 Browser Agent 的跨应用能力（10 月 28–30 日发布，7 日补推）

发生了什么：10 月 28 日 1.0.0 和 10 月 30 日 1.0.2 发布后，agent-desktop 已以 Vercel Labs 名义提供 macOS、Windows、Linux 的 Rust CLI 与 C ABI。它读取操作系统 Accessibility Tree，并给可操作元素绑定含 Snapshot ID 的 Ref；当 UI 改变时返回 STALE_REF 或 AMBIGUOUS_TARGET，让 Agent 重新观察，而不是用旧坐标误点。默认通过系统无头接口操作，必要时再启用物理输入。

为什么值得看：Browser Agent 如果要操作浏览器设置、文件选择器、系统授权和原生桌面 App，网页 DOM/CDP 并不足够；这个项目提供了结构化的另一半。工程启发：为 CDP/WebDriver 与系统 Accessibility 两类工具统一 Ref 生命周期、错误码和重试语义。它本身不是浏览器，也没有公开独立跨平台任务成功率基准；快照和剪贴板可能包含敏感信息，应隔离日志与模型权限。

5. LiteRT-LM：WebGPU 并发加载模型的共享状态拆分，仍是候选 PR（24 小时内）

发生了什么：11 月 2 日 01:34 UTC 创建的 google-ai-edge/LiteRT-LM PR #4332 拟将 streamed_weights_manager.cc 内的全局权重流状态移入由互斥锁保护的 WeightsStreams 单例，并按线程记录当前编译的模型类型，以适应 WebGPU 权重上传回调与 CompiledModel::Create() 同线程执行的行为。目的是让多线程同时加载 Engine 不再互相干扰。

状态与边界：目前是未合并 PR，没有可核实的端到端内存与加载延迟改善数字；不把设计意图写成已经发布的能力。工程启发：AI Native Browser 中多个 Tab/Agent 共享推理服务时，权重缓存、模型实例、编译上下文及 WebGPU 回调线程需要明确生命周期和并发契约，并通过双模型并发加载与取消测试验证。

浏览器技术

Firefox/Metal Shader 相容性比 API 是否支持更细。MoGe-3 WebGPU 报告 ORT 1.24.3 WGSL 输出的索引数组别名可能在 Firefox Metal 转译中产生不一致类型，导致 Split/Concat Pipeline 编译失败。其候选处理仅合并相同布局的别名名称，不改 Buffer 访问及 FP32 运算，并用参考结果验证。这是开发者仓库中的具体兼容处理，不等于 Firefox 官方修复已发布。源提交。

本次没有核实到过去 24 小时值得单列的 Chrome、WebKit、Firefox、Edge、Opera、Brave 官方架构或 Web API 新公告，不重复 10 月下旬已推送的 Opera WebAI 和 Firefox Smart Window。

端侧 AI

模型分发与计算正确性应一起优化。MoGe-3 WebGPU 使用约 1.24 GB 的分块初始资源与浏览器缓存，尝试在后续下载恢复原始 FP32 权重；其部分 24-bit 存储属于精度取舍，在执行前扩展到 FP32，并不意味着等同于完整原始权重。每次模型升级必须同时检查权重哈希、视觉输出误差及跨设备缓存命中。LiteRT-LM 的 WebGPU 权重流并发 PR 则提醒：多个 Agent/Tab 的模型加载不能依赖无保护的全局状态。

浏览器 × AI

三个接口边界需要统一：BrowserBear 负责用户真实 Chrome Profile、标签与 CDP；agent-desktop 负责系统原生控件及 Accessibility Ref；LiteRT-LM 负责 WebGPU 模型权重与实例生命周期。产品不宜让 Agent 自行拼接这三套权限。可设计统一操作结构：Browser/OS/Model Target、Ref/Revision、权限结论、实际状态、可重放回执。

Browser Self-Improvement

本期重点：Skill 只有经过独立复演，才应进入长期可用资产。Browser Harness 的六站点 Skill 是已合并的明确案例；MoGe-3 的跨浏览器数值比较与性能实验则展示了 Kernel 变体的独立正确性门槛，但均尚未触达浏览器正式 Canary/Telemetry 自动学习闭环。

迁移建议：先做最小的 Skill Promotion Gate。每份由 Agent 发现的测试或操作 Skill 都保存来源 URL/版本、匿名化状态、输入、退出条件、预期输出；由独立 Harness 在冷启动与新 Session 中执行，失败时生成反例；只有通过之后才能放入共享 Skill 库，后续每周用新浏览器版本重新检验。这个机制可先在 Chromium/Firefox/WebKit 的自动化回归上落地，而无需立即尝试让 Agent 改浏览器内核。

今天的一个判断

Browser Agent 与端侧 AI 的下一项共性工程能力，是把“观察到的状态”变成可重复验证的契约。对 Agent，它体现为真实 Profile/Tab、Snapshot Ref 与 Skill 的独立复演；对 WebGPU，它体现为模型权重、Shader 变体、跨浏览器数值结果和 Benchmark 证据。优先完成独立 Verify 与失败经验回流，比先追求端到端自动改 Chromium 更能快速产生可量化的收益。
