浏览器 × 端侧 AI 日报

今天没有值得强行填充的 Chrome / WebKit / Firefox 引擎级新发布；更重要的变化发生在 Browser Harness：真实浏览器控制正在从固定 API 演化成“Agent 能补 Helper、能验证、能积累能力”的可进化执行层。

2026-08-31 · 过去 24 小时优先 + 一周内未推送高价值补充

今天最值得看

Browser HarnessReal Browser

Browser Use 的 browser-harness：Agent 直接连接真实浏览器，并在任务中补写缺失 Helper

browser-harness 的核心做法是通过一个可编辑的 CDP websocket 连接用户真实浏览器；底层 harness 代码保持受保护，而 Agent 可以在本地 workspace 中创建可复用 helper。8 月 30 日项目继续合入真实键盘事件、Recorder timeout、Chrome probe 等修复。

为什么值得关注：这不是“模型会点网页”这么简单，而是 Browser Harness 开始具备明确的能力生长边界：固定 runtime + 可写 helper + MCP 暴露 + 真实 Session。

GitHub

Self-ImprovementDistributed Experience

EvolveNet：不集中原始轨迹，只合并各环境学到的 Harness 改动

EvolveNet 让共享 Harness 下发到不同数据本地的 Agent 部署，各自基于本地 workload 演化；回传的不是原始任务与轨迹，而是程序级 adaptation，再通过 scope-typed、evidence-guided aggregation 合并。

浏览器工程迁移：Windows / macOS、GPU 厂商、设备档位、地区网络环境可以各自学习最合适的诊断/验证 Harness，再把经过证据标注的改动合并，而不需要集中原始用户数据。

arXiv: 2608.04968

Skill EvolutionKnowledge Layer

WikiSkill：把“原始经验、持久知识、可执行 Skill”明确拆成三层

WikiSkill 不再让 Skill 直接从零散轨迹反复重学，而是先持续把执行经验整理到持久 Wiki，再由后续 Skill evolution 使用。论文还观察到 Skill 能跨模型迁移，其他模型演化出的 Skill 有时优于自演化 Skill。

启发：Browser Self-Improvement 的 Learn 层不该只有 Skill Store；需要一个位于 raw trajectory 与 executable skill 之间的知识编译层。

arXiv: 2608.27454

浏览器技术

Browser Harness 的可靠性越来越像传统浏览器输入/状态系统问题

8 月 30 日 browser-harness 连续修正 printable key 的 physical code、浏览器 OS 与 host OS 的 modifier 差异、Recorder screenshot IPC timeout，以及本地 Chrome probe。这些问题都说明 Browser Agent 的可靠性瓶颈经常不在 reasoning，而在输入事件语义、平台差异、状态探测和超时边界。

工程启发：Browser Agent benchmark 应单独测“动作语义正确性”，例如 key/code/modifier、IME、frame lifecycle、navigation race、download/upload、cross-platform modifier，而不是只看最终 task success。

端侧 AI

EvolveNet 对端侧 Agent 的价值高于今天的一般模型发布

如果 Browser Agent 真正在用户设备运行，最有价值的经验往往来自本地真实环境，但原始页面内容、历史记录和企业数据不适合集中上传。EvolveNet 的“经验在本地提炼，只上传 adaptation”非常适合端侧 Browser Agent。

此前关注的是“如何让 Agent 进入真实浏览器”；browser-harness 把问题再推进一步：进入之后，哪些能力固定在 runtime，哪些允许 Agent 学习后写进 helper / skill。

关键边界：可进化部分应该是 Helper / Skill / Workflow，而不是任意修改 Browser Security Boundary、权限协议或底层 CDP 约束。

Browser Self-Improvement

今天的新关键词：Knowledge Compilation（知识编译）

过去几天我们已经补了 Memory Hygiene、Executable Learning、Reviewable Improvement、Trusted Learning、Privilege-Preserving Learning、Selective Learning。WikiSkill 提醒我们，还缺少一个中间层：把高噪声轨迹编译成可复用、可审计、但尚未直接执行的工程知识。

Raw Trajectory
   ↓
Selective Learning
   ↓
Evidence / Provenance Filter
   ↓
Persistent Engineering Wiki
   ↓
Knowledge Compilation
   ↓
Executable Skill / Helper
   ↓
Benchmark + Review + Trust Gate
   ↓
Trusted Runtime
为什么重要：如果每次都从 trajectory 直接生成 Skill，很容易把偶然步骤、过时版本条件和不安全操作一起固化。先进入知识层，再编译为 Skill，更容易做版本、证据、适用范围和过期管理。

EvolveNet 补上多设备 Browser Self-Improvement

浏览器工程天然异构：Windows/macOS、Intel/AMD/NVIDIA、不同网络、不同企业策略。与其强求一个中央 Agent 见过所有 Trace，不如让局部 Agent 学出 adaptation，再带 scope 和 evidence 合并。

今天的一个判断

Browser Self-Improvement 的长期形态越来越不像“一个 Agent 不断改自己”，而更像一个受约束的编译与发布系统：

Telemetry / Regression
      ↓
Trajectory
      ↓
Select + Verify + Provenance
      ↓
Engineering Knowledge
      ↓
Compile to Helper / Skill / Harness Patch
      ↓
Benchmark / Review / Trust Gate
      ↓
Scoped Deployment
      ↓
Revalidate / Merge / Decay

因此今天补上的原则是 Knowledge Compilation：不要让经验直接变成可执行能力；先把经验变成带证据和适用条件的知识，再把知识编译成 Skill。
