今天最值得看

1. Foundry Local：Qwen3.8-27B 本地 Coding，具体优化已公开

发生了什么：微软 11 月 5 日发布 Bring Agentic Coding On-Device with Foundry Local。使用 ONNX Runtime，在 NVIDIA GPU 上为 Qwen3.8-27B 增加 DFlash2 推测解码、CUDA Graph/Kernel 优化、INT4 权重、KV Cache 量化、CPU Offload、Prefix Cache 和 Continuous Batching。官方称 4-bit 权重约 18GB，24GB 显存可运行最长约 64K 上下文；32GB 以上在适当配置下可扩大上下文。提供 Foundry Local CLI ≥0.13.0 与 GitHub Copilot BYOK 接入流程。

为什么值得关注：优化焦点不只在算子计算，还覆盖长上下文重用与多个 Agent 并发调用。官方使用真实 GitHub Issue 数据集对比 llama.cpp，声称在 RTX 5090 和 DGX Spark 测试平台具有速度优势；文章图表是厂商测量，尚无本期独立复现。当前主要针对桌面 NVIDIA CUDA，不是手机端 WebGPU 的现成实现。

浏览器工程启发：Browser AI Runtime 也需要统一的模型下载、缓存、KV Cache、会话并发和端云切换；可参考其测量维度，但 Safari/Android/WebGPU 应独立验证内存、首 Token 和后台恢复，不直接套用 CUDA 数据。

2. Safari Technology Preview 256：WebGPU texture swizzle、显存回收及视频解码改进（7 日补推）

发生了什么：WebKit 11 月 4 日发布 Safari Technology Preview 256，覆盖 WebKit 323398…324653@main。WebGPU 新增 texture-component-swizzle，允许 GPUTexture.createView() 的 swizzle 参数重排/填充纹理通道；同时修复 GPUTexture 销毁后因旧 GPUBindGroup 引用而无法释放 GPU 内存，并优化 WebGPU OffscreenCanvas 读回。媒体部分修复 WebCodecs FLAC 解码失败、超过双声道的 Opus 解码、MediaRecorder 丢失最后一段数据、MSE 视频 Track flush 后卡死等问题。

为什么值得关注：这类变化直接影响浏览器端侧视觉和语音推理、多模态视频管线以及显存可靠性。它是Safari Technology Preview，不是 Safari 正式版全量可用的证明；没有公开量化 WebGPU 读回速度提升幅度。

浏览器工程启发：在多 Tab 推理/绘制压力下测试 GPU Buffer/Texture 生命周期、视频与推理相互争抢 GPU、冷/热切换和 AudioDecoder 兼容；将 GPU 内存泄漏作为 Browser Runtime 的独立回归项。

3. Lightpanda：网页动态 WebMCP 工具能够被 Agent 可靠发现，且不污染模型工具声明

发生了什么：Lightpanda PR #4454 于 11 月 5 日 19:11（北京时间）合并。过去只在导航结果列出 WebMCP 工具，但多数页面在 load 之后才注册，导致 Agent 不知道工具存在。补丁在页面工具集合变动后，于下一次相关工具结果中附带工具名称、说明、输入 Schema 和提示；通过 ModelContext 的 generation 计数和 frame/loader 标识避免重复与过时通知。

为什么值得关注：开发者明确没有把网页动态工具直接加入模型顶层 tools：这样会破坏 Prompt Cache、让恶意或错误 Schema 拒绝整次模型请求、还会把网页文本提升为高信任指令，导致工具名冲突。补丁描述提供了一个真实网站延迟注册工具的人工验证场景。状态：PR 已合并，未见独立的大规模成功率基准。

浏览器工程启发：把网页工具视为“来自当前 Origin 的不可信能力清单”，经 Browser Runtime 验证后作为结构化数据回执供 Agent 决策，而不是直接变成系统工具声明；同时绑定 Frame、Loader、Version，防止导航后使用旧能力。

4. Browser Harness：独立复验 Skill，同时因 robots.txt / 条款拒绝晋级

发生了什么：Browser Harness #975 于 11 月 6 日 07:53（北京）合并四个站点 Skill（PokeAPI、NVD、TVmaze、Treasury Fiscal Data）。作者说明每段代码先在真实未登录浏览器执行，再由另一 Agent 在新的浏览器中原样复演；审查修复部分描述与 API 事实不符的地方。作者也因服务条款限制主动丢弃了 Roblox、Coinbase 候选。此前 #972 于 11 月 5 日 08:11（北京）删除一个 NBA Skill，因为该站 robots.txt 针对 AI Agent 的规则更严格，虽然通配 User-agent 规则允许。

为什么值得关注：这里最重要的是“Skill 验证通过仍不一定可以发布”：功能正确性、来源合规和权限条件是彼此独立的晋级门槛。限制：这些是项目 PR 记录的单次结果，未证明 Skill 在后续网站改版后能自动修复。

浏览器工程启发：针对 Browser Agent Skill 库设置三层独立门禁：可重放正确性、站点/API/机器人访问政策、长期可靠性；失败和撤下的 Skill 也需沉淀成规则和测试。

5. Microsoft Foundry azd 扩展 GA：测试、评估、优化与部署配置开始进入同一工程链路

发生了什么：微软 11 月 5 日发布 Microsoft Foundry extension for Azure Developer CLI 1.0 GA：在版本化的 azure.yaml 中维护 Agent 配置，使用 azd ai agent run 本地测试、Agent Inspector 检查请求/响应、azd ai eval generate 生成待审核的评测数据与准则、azd ai eval run start 重跑评测，并可用 azd ai agent optimize 基于配置好的评测提出候选优化（明确要人工审查后再部署）。

为什么值得关注：这不是浏览器原生功能，但把 Agent 的配置、执行记录、基准和发布整理成了一套可在 CI 复用的开发流程。需要 Azure 资源与配额，部分模型及特性仍有预览限制；官方文章未给出浏览器特定 Benchmark 的改进幅度。

浏览器工程启发：Browser Harness 可照此把 Prompt/Tool/Skill、固定测试集和运行环境一起版本化，测试在独立环境执行，再依据 Canary/Review 回执决定是否升级策略。

浏览器技术

WebKit：Safari TP 256 中除了 WebGPU 之外，SVG 2 文本布局、Canvas 文本绘制属性、CSS font-palette-mix()，以及 Web Inspector Timelines 缺失帧/Call Tree 内容等修复也与开发者体验相关。特别值得关注的是 requestIdleCallback() 使用实际 60Hz 帧周期修正空闲调度，不再把工作安排在帧截止之前。详见 官方 Release Notes。

Chrome DevTools MCP 候选增强：PR #3384 提出请求覆盖（network overrides），能在受控页面将生产资源替换成本地文件或测试服务器资源，用于修改前后对比。作者报告 1,828 项测试通过，但截至本期仍为待合并 PR。这为浏览器差异验证提供潜在测试能力，不能按已发布功能使用。

端侧 AI

本期重点是微软公开的 Qwen3.8-27B 本地 Coding 优化路径。与手机端 0.5B～3B 小模型不同，27B 的部署代价高，因此其工程价值更多体现在推测解码、量化权重、Prefix Cache 与并发调度。跨到 WebGPU/WASM 需要分别处理浏览器显存预算、GPU Process 边界与权限，不能将 CUDA 的 Benchmark 当成浏览器性能。

WebKit TP 256 对 GPUTexture 生命周期和 WebGPU OffscreenCanvas 的修复则说明：浏览器端侧推理的持续稳定性不仅依赖模型 Kernel，也依赖图形运行时的资源回收、读回及媒体协作。

浏览器 × AI

WebMCP 动态工具发现：Lightpanda #4454 的“页面 Schema 只作为工具结果”与新发现的真实 Safari/Dia/Chrome Profile MCP 桥形成两类实现。前者解决网页作为工具提供者时的动态能力发现与信任分层；后者解决 Agent 作为浏览器操作者时的授权和状态。产品层应该分离这两类能力：网页不能修改 Browser Runtime 的高权限工具；真实 Profile 操作需按 Origin/Tab/动作类型授权，并记录谁执行了什么。

今天的一个判断

Browser AI 的下一项基础能力应是“动态能力发现 + 可验证权限 + 可复演结果”，而不只是更长的工具列表。WebMCP 清单可以由网页迟到注册，但不应获得系统级工具信任；Skill 可以验证通过，但仍应因来源政策不满足而拒绝晋级；本地 Coding 模型能提高计算效率，但不能替代 Browser Runtime 自身的隔离、可观测与基准测试。对 Chromium/WebKit/Firefox 都有现实迁移意义。
