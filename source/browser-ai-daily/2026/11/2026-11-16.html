1. Brave：用部分盲化伪随机函数保护搜索点击，同时提高批量抓取成本（11/11 官方方案）

发生了什么：Brave Search 11 月 11 日介绍一套准备推出的结果链接保护方案：结果的真实目标地址先加密，用户浏览器通过 partially oblivious pseudorandom function（部分盲化伪随机函数，POPRF）取得仅能解开一个链接的密钥。浏览器在客户端解密并直接访问目标网站，Brave 服务器可计数密钥请求，却无法得知用户究竟点击了结果页中的哪一条链接。

技术究竟新在哪里：普通搜索跳转链接由服务器看到目标 URL，而这套设计将“控制每个结果的解密成本”和“服务端不知道具体点击目标”结合起来。它不是发明全新的密码学原语，而是对 Web 搜索的隐私与反爬需求做出了新的协议级组合。工程启发：Browser Agent 和搜索系统可以研究如何在提高批量自动访问成本时，避免把人的点击轨迹集中采集到服务端。

证据与成熟度：这是 Brave 官方技术设计与上线预告，不是已通过第三方生产流量审计的部署结论。没有 JavaScript 时会回退至传统重定向，Brave 将可能看到目的地址；复制出来的跳转链接可能过期，也有被滥用于钓鱼的风险。新颖性：高；值得深挖：高。应验证密钥请求与会话关联、客户端不可追踪性、真实机器人经济成本及兼容性。来源：Brave 官方架构文章（2026-11-11）。

2. Browser Immune System：一个 WebGPU 端内 4B 安全模型，在浏览器执行快速分类与按需解释（11/11 论文）

发生了什么：研究者在 11 月 11 日提交 Browser Immune System (BIS)，把 40 亿参数的安全模型 alias-web 量化到 4-bit，编译成约 2.44 GB 的 WebGPU 图，在 Chrome 和 Firefox 扩展中本地执行。每个威胁类别使用一次定向判别（System 1），需要时才用同一权重生成文字解释（System 2）。

技术究竟新在哪里：不是“浏览器里运行一个 Chat 模型”，而是把固定类别安全判断改成单次前向判别、无 Token 解码，让大模型先在本地快速回答有类型的问题，昂贵的解释延后到需要时。作者报告单个类别问题约 150 ms；整页扫描为 0.9—6.4 秒，不能把单次决策延迟误写成整页检测延迟。

验证与限制：作者的 8 个合成网页中判对 7 个，micro-F1 为 0.71；11 个真实网页的初步实验显示，部分正常脚本和登录表单被误报。它仍是论文和实验扩展，不能当作生产级防护；模型下载、显存、能耗与误报需要进一步评估。新颖性：高；值得实测：高。建议对比固定规则与本地模型的误报、端侧热启动、每页总耗时，并在 Android/Safari WebGPU 场景检验。来源：原始论文、模型权重、相关端侧 Runtime 研究代码（前期项目，非 11/11 新仓库）。

3. WebTrap Farm：把 Browser Agent 的安全问题归因到 Harness，而非只测模型（11/09 论文）

发生了什么：11 月 9 日提交的 Harness Matters 提出 WebTrap Farm，将 Web Agent 拆为目标解释、网页感知、规划决策和动作执行四个阶段，对恶意用户指令、页面提示注入和欺骗性界面进行跨 Harness 评估。

技术究竟新在哪里：它加入成对的可用性校准任务：Agent 没有做危险动作，可能只是不会操作页面，而非真的抵挡了攻击。通过先校准正常任务能否成功，再统计防御结果，可以避免把无能力误判成安全。研究报告开源 Harness 样本的总体攻击成功率为 32.55%，统计模型也发现 Harness、底层模型及两者交互均影响安全结果。

证据与限制：这是论文的实验结论，不能推导出所有 Browser Agent 具有同样风险，亦不是已在 Chromium/WebKit/Firefox 内核完成的安全改造。新颖性：中高；值得深入研究：高。最适合迁移为 Browser Agent 验证基建：同一模型、同一任务，在不同 Harness 或策略下进行配对测试；分离任务成功率与危险动作率。来源：原始论文与实验方法。

浏览器技术

Brave 端侧隐私：11 月 12 日正式介绍 Brave 桌面版 1.98 起在图片下载和上传两个环节去除 Meta 图片 IPTC 字段中的 FBMD 标识。下载保护保存的文件，上传则使用清理后的副本而不修改本地原文件；这是资源进出浏览器时的隐私边界改造。Brave 说明尚不清楚 Meta 是否实际把该字段用于跟踪，不能写成已证实追踪行为。建议检查 JPEG/IPTC 内容保留、破损文件回退与上传兼容；iOS/Android 仍是后续计划。来源：Brave 官方技术说明（11/12）。

Chromium / WebKit / Firefox / Edge / Opera：本观察窗口未核实出比上述三项更值得报道的正式新架构发布，不用常规版本更新和修复补齐。昨日已报道的 WGSL Shader Print、Subgroup Matrix FP8/BF16、CrUX Soft Navigation 不再重复作为今日头条。Chrome 158 计划于 11 月 17 日在 Stable 移除 XSLT（保留 Origin Trial/企业政策例外），是已有计划的临近兼容性里程碑，不是 11/16 首发；需要关注遗留 XML/XSLT 站点。来源：Chrome XSLT 迁移说明。

端侧 AI

BIS 展示了分类判别与生成解释分离的具体端侧系统实现。对于浏览器/移动端推理，应把单次模型判断延迟、整页检测耗时、4-bit 量化后结果一致性、GPU 常驻内存、冷加载和误报分开度量。它验证了研究可行性，但不构成真实站点广泛安全准确率的证据。过去 24 小时未核实到更高优先级的新型推理算法或 Runtime 正式发布。来源：BIS 论文。

浏览器 × AI

Brave 的私密搜索跳转提醒我们：Browser Agent 的海量查询和抓取会反向推动 Web 服务重构访问协议。BIS 则提示另一个方向——浏览器可以在页面数据离开设备前，由本地模型完成初步威胁判断。两者都不是传统“给浏览器加一个 MCP 封装”，分别代表协议层和计算层变化。浏览器产品、Agent 和内容服务需要分别处理隐私、成本与误报，而不是靠 Prompt 解决。

今天的一个判断

浏览器 × AI 真正值得投入的方向，不是更多控制按钮，而是把安全和性能要求做进协议、推理执行路径与独立评估器。今天的三个补推分别提供了：隐私不依赖服务器自律的协议尝试、本地 GPU 安全判别的实验路径，以及防止评测高估安全性的校准方法。推荐优先精读 Brave POPRF 协议和 WebTrap Farm 实验设计，再决定是否复测 BIS。
