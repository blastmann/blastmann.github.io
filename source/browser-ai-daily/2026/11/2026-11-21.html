今天最值得看｜3 项七日补推

1. Edge Decisions API：浏览器内 AI 从“逐字生成答案”走向“单次计算返回结构化判断”（11/19 官方）

发生了什么：Microsoft Edge 于 11 月 19 日正式公布 2.3B 参数的 Aion Instruct 开放权重，成为 Edge 内置小语言模型并替换 Phi-4-mini；同时将 Prompt API 从 Canary/Dev 开发预览推进到可供真实网站注册的 Origin Trial。更值得关注的是实验性的 Decisions API：允许网页用 DecisionModel.create() 声明 boolean、choice、score 问题，通过 model.decide(input) 返回选项、概率、置信度及预期评分，不需要逐 Token 生成文本。Decisions API 目前仅在 Edge Canary/Dev 开发者预览，尚非正式标准。

技术新在哪里：将语义判断作为浏览器受控、带 Schema 的推理原语。对于页面工具选择、表单分类、输入检查、内容排序，应用可以限定输出范围，一次计算多个问题，并按不确定性选择是否继续请求更强模型。相比 Prompt API 再生成 JSON，这种设计减少生成式输出解析与连续解码成本。不过“概率已充分校准”“在所有设备都更快”仍需实测，不能直接当作事实。

重要去重：这不是 11/19 才出现的新算法或 Edge 首创的跨浏览器 API。Opera 早在 10/27 的 WebAI 预览里就宣布支持 Decisions API；Google Chrome Built-in AI 团队也维护相关早期 Explainer，明确尚未批准在 Chrome 正式发布。11/19 的新进展是 Edge 的开发预览、Aion 开放权重及 Prompt API Origin Trial，不能写成 Decisions API 首次诞生。

验证及成熟度：微软公布了 Aion 模型卡：MIT 许可、2.29B 参数、32K 上下文、21 层 sliding-window 与 7 层 full-attention；这些参数可独立检查，但 Edge 实际延迟、内存、功耗以及分类概率校准尚无本期独立复测。实际执行高风险操作仍须独立权限检查，模型高置信度不能当授权。

技术新颖性：高（浏览器内计算接口与系统集成），并非新模型算法；值得深入研究/实测：非常高。建议用 100—500 条相同页面意图，在 Edge 预览中比较 Decisions API、Prompt API JSON 输出与传统规则，在 P50/P95、冷启动、峰值内存、错误分类、概率校准、授权隔离上做对照；记录硬件和模型下载状态。

原始来源：Microsoft Edge 官方（11/19）、Decisions API Explainer、Aion 开放权重与模型卡、Opera 10/27 先前预览的独立时间线。

2. NVIDIA：稀疏注意力的瓶颈从 Attention 移到了“寻找该关注哪些 Token”（11/17 官方工程深挖）

发生了什么：NVIDIA 11 月 17 日发表 Co-Designing Sparse Attention for Efficient Long-Context Inference，比较生产级 FP8 Kernel 的 Indexer、Top-k 与 Core Attention。它不是 11 月 17 日发明 Sparse Attention，而是用硬件性能测量，说明何种模型结构能让 GPU 真正得到收益。在作者的 128K 输入长度示例里，DeepSeek V3.2 稀疏注意力的 Indexer + Top-k 占单层 Prefill 约 47%，说明计算量减少后，选择工作反而成为新的成本中心。

技术差异：减少选择器要扫描的 Key、缓存或共享索引、复用前一步 Top-k 结果，以及把 Top-k 与 Indexer 融合，往往比简单调小选出的 k 更有效。作者的特定 CUDA Decode Kernel 实验报告 Guess-Verify-Refine Top-k 比通常的 radix select 快 2.1—2.4 倍；选中连续大块而不是分散 Token 也更适合 GPU 合并读取。这些都是特定组件及硬件上的作者测量，并非端到端模型 2.4 倍加速，更不能推广为手机/WebGPU 效果。

技术新颖性：中高（系统分析与模型/硬件协同设计，不是新算法首发）；值得研究：高。工程启发：在端侧模型 Profiling 中把 Attention 拆分成 Indexer、Top-k、KV 访问、实际 Attention 四类独立耗时，分别评估 Decode 与 Prefill。若探索 WebGPU，需按设备支持重写 Kernel，并重新验证精度、内存与功耗，不能照搬 CUDA 数据。

来源：NVIDIA 11/17 原始技术分析与性能数据；文中给出 FlashInfer 的选择器融合相关实现供进一步复核。

3. WebKit：WKWebView 开始在每次导航时原生表达 GPC 隐私偏好（11/18 官方 API）

发生了什么：WebKit 11 月 18 日公开在 iOS/iPadOS/visionOS/macOS 27 中的 Global Privacy Control（GPC）WebKit 接口。原生应用可在导航决策返回的 WKWebpagePreferences.globalPrivacyControlEnabled 设值；SwiftUI 的 WebPage.NavigationPreferences.isGlobalPrivacyControlEnabled 也提供对应入口。启用后，浏览器在主文档、子框架及子资源请求中带 Sec-GPC: 1，并通过 navigator.globalPrivacyControl 暴露一致的偏好。

为什么重要：隐私偏好不必由页面 JavaScript 事后注入，WebView 宿主可以把它作为导航级策略，覆盖请求头和 DOM。它为浏览器内跟踪防护、App 内嵌网页和不同导航策略的可验证一致性提供了更原生的接口。

成熟度与边界：GPC 标准早已存在，W3C 2026-09-24 文档仍为 Working Draft；本次新的是 WebKit 宿主 API，而不是首次发明 GPC。发送偏好信号并不自动阻断追踪代码，也不能保证服务器一定遵守。不能把 27 平台 API 宣称为所有当前稳定设备均已支持。

技术新颖性：中高（WebKit 宿主导航策略与网络层整合）；值得实测：高。验证导航前设置、跨域 iframe、资源请求、重定向与页面内再次导航时 Header/JS 是否一致，并检查更改偏好后的页面缓存行为。

来源：WebKit 官方 API 说明（11/18）、W3C GPC Working Draft。

浏览器技术

WebKit/Safari：本期新增可验证的 GPC 宿主 API 设计，适合研究内嵌 WebView 的隐私边界，细节见上。Chromium/Chrome、Firefox、Edge、Opera、Brave：在本 24 小时窗口内未独立核实足以作为全新浏览器内核算法的首发。Edge 11/19 的 AI API 是七日补推；Opera 的 10/27 先发已经明确去重，Mozilla 11/20 的 iOS 浏览器引擎政策文章属平台政策观察，不冒充引擎技术发布。

端侧 AI

Aion：2.3B 开放权重（MIT）使系统内置模型的精度、内存及热/冷启动性能具备进一步独立测量基础；目前不能拿 Edge 的“更快、更广泛可用”宣传语代替跨设备数据。稀疏推理：NVIDIA 的工程分析提醒我们：Attention 变稀疏之后，还必须测量谁来决定“稀疏到哪里”。尤其对移动端与 WebGPU，数据搬运可能比算法 FLOPs 更关键。

浏览器 × AI

低成本决策层：可以构建 input → fixed schema → local decision/confidence → policy gate → execute/ask，用内置模型做低风险分类，保留云端模型或人工确认作为复杂和高风险场景的后备。该结构是工程建议，不是 Edge 已提供完整 Agent Runtime。 权限约束：即使分类输出置信度 0.99，也必须单独经过工具授权、业务检查及最终状态核对。

Browser Self-Improvement

本期没有确认新的完整 Observe → Diagnose → Improve → Verify → Learn 自主闭环。Decisions API 可成为 Diagnose/策略选择的低成本能力，GPC 可以成为 WebView 安全和隐私验证的一项回归信号，NVIDIA 的指标分解可帮助诊断模型运行效率；但三者都没有证据表明已实现自动提交浏览器补丁、独立 Benchmark/Canary 和经验回流，因此绝不称为 Browser RSI 成果。

此前 11/20 已报道的 Chrome Mirror Dimension 仍是有价值的验证环境参考，本期不重复当作新发布。下一步值得观察的是：是否存在系统能够凭真实 Trace/Crash/浏览器 WPT，自动提出改动，再经跨引擎回归、Canary 和长期证据沉淀。如果只做到推荐修改，没有可信的独立结果检查，仍不是完整闭环。

今天的一个判断

浏览器端侧 AI 值得优先建设的是“不生成文本的快速判断层”，但它只有在权限、置信度和实测成本都可控时才是真正的新平台能力。本期我最建议实测 Decisions API 与 Prompt API 在相同页面任务上的 P95、冷启动和错误率；其次研究 NVIDIA 的 Indexer/Top-k 拆解方法。对 WKWebView 工程，GPC 的真机网络/DOM 一致性也值得作为明确的回归测试。
