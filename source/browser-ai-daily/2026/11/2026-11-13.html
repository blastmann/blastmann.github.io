今天最值得看

1. Chrome 官方：现代 Web Guidance 让 Coding Agent 默认考虑跨浏览器回退（11/12 新文章）

发生了什么：Chrome for Developers 11 月 12 日发布《跨浏览器默认兼容：Baseline 回退方案如何工作》，解释 Modern Web Guidance 为 Agent 提供 web-features 的 Baseline 支持状态、支持版本和经过核实的回退实现。这是新文章，不是新仓库：项目创建于 3 月 23 日，1.0 已于 11 月 10 日推出。

为什么重要：Widely Available API 可直接使用；Newly Available 或 Limited Availability 应提供 Fallback。例如 <dialog closedby> 在 Safari 可能要走 JS 回退，而 Chrome/Firefox 可运行原生功能。文章建议 Agent 同时接入 Chrome DevTools、Firefox DevTools MCP（BiDi）与 Safari safaridriver --mcp，验证原生和回退两条路径。只在 Chrome 测试会漏掉 Safari 的代码。

工程启发：把 Baseline 兼容数据作为 Agent 工具输入，并为原生/回退分支各生成可复现 E2E；不要仅靠 Prompt 假定兼容。项目 README 展示 11 月 8 日 Codex 等模型的自有对照评测（如 54%→82%），属于作者结果，尚无独立生产验证。来源：Chrome 官方、GitHub。

2. Playwright：多 Agent 标签所有权与可恢复 Tab Group 已合并（11/13 02:54）

发生了什么：Playwright #44047 于 11 月 12 日 18:54 UTC 合并。浏览器 Extension 维护所有客户端的 Tab Owner 表；客户端只能控制自己拥有的 Tab，不允许更改浏览器级 Cookie 和权限。用户可以选择共享标签或 Tab Group，客户端断开后 Group 保留，其他客户端可接管。

为什么重要：真实浏览器/登录态共享不应让 Agent 互相串台。代码已合并，但不代表已进入正式 npm/扩展发布，也没有独立权限审计。工程启发：把 Owner、Tab Group、Session 和接管记录建成 Runtime 的明确数据结构，执行前检查权限，执行后回读结果。来源：PR 与源码。

3. agentwatch：读现有 Claude Code 记录的 Rust 多 Agent 观察台，并有自我改进提案入口（新仓库）

发生了什么：agentwatch 创建于 11 月 12 日 18:08 UTC（北京时间 11 月 13 日 02:08）。它从 ~/.claude/projects/ 读取 Session 和子 Agent 记录，构建本地浏览器时间线、卡住/失败识别与只读 MCP 工具。agentwatch_wait 用事件等待代替 Agent 的重复轮询，agentwatch_errors 分类失败，agentwatch_snapshot 提供结构化上下文。

为什么重要：额外的 agentwatch_suggest_improvement 和 agentwatch-evolve 把未满足的需求记录为建议，在用户 Fork 的候选分支上修改代码、运行 Rust/Node 一致性测试，经审批再推动 PR。当前仅是具备候选改进能力的早期工具，不是已证明可自主长期学习的系统。

工程启发：为 Browser Harness / Agent Manager 提供只读事件索引、等待、故障分类、Parity Oracle 与候选改进工具；既减少 Poll 上下文开销，也让错误可被验证。作者声称约 50 MB 内存、空闲 0.8% 单核，尚无第三方复测。只支持其声明的 Claude Code 记录格式，不能假设兼容 Herdr 等全部运行时。来源：README 与测试脚本。

4. Chrome DevTools MCP：将一次操作期间页面发生的错误与操作回执绑定（待合并）

发生了什么：#3431 于 11 月 12 日更新，提出 click、fill、navigate_page、evaluate_script 等工具响应直接包含该调用期间的 Console Error、资源加载错误、CSP 错误，上限 10 条，剩余错误可通过 Console 工具查询。

为什么重要：避免 Agent 把“点击返回成功”误判成“页面业务已成功”。提交者明确指出当前不能捕获跨进程 iframe 的错误，也无法覆盖两次调用之间产生的所有事件。当前是开放 PR，不能误记成 1.13.0 的正式能力。工程启发：所有操作回执应包含 Action ID、Frame/Worker、起止时间、相关错误和最终状态核验。来源：PR。

5. webgpu-particles-bench：JS/WASM/WebGPU 对照不隐藏数值错误（新仓库）

发生了什么：webgpu-particles-bench 创建于 11 月 12 日 14:41 UTC（北京时间 22:41）。它用同一粒子模拟规则分别在 JS、Rust/WASM 与 WebGPU 执行，从百级到千万级粒子测 p50/p99、GPU Timestamp 与数值偏差，并保留 results.json、复现命令、trace-outlier.mjs。

为什么重要：作者在 Apple M2 Max / Chrome 157 的 100 万粒子、100 步对比中，WASM 与 JS 一致，但 GPU 有一个粒子的位置/速度误差超出 0.001 容差。它是很好的“加速不等于正确”的例子。工程启发：WebGPU 模型 Kernel 也应保留 CPU Golden Reference、数值容差、失败输入和尾延迟，而非只报告吞吐。属于作者的早期单机实验，未经独立跨浏览器复测。来源：源码和原始结果。

浏览器 × AI

Playwright 解决多 Agent 标签归属，agentwatch 提供运行时间线与故障证据，DevTools MCP 候选改动 让网页错误与操作回执关联。三者适合组合为一个受控 Browser Session：控制前验证 Owner，操作期间收集 Console/Network，完成后由独立会话判断效果。

另有 DevTools MCP #3473 提出可选 --repl 批量执行页面操作和检查，试图减少模型轮次与 MCP 往返。目前是Draft PR，未发布，需要额外验证脚本权限、取消和失败后副作用。

今天的一个判断

让 Agent 用上更先进的 Web API 并不难，难的是证明它在 Chrome、Firefox、Safari 上都按预期工作；让多个 Agent 连接真实浏览器也不难，难的是确认每一次操作属于谁、是否真的生效、失败证据能否重放。 这两类基础验证能力，比再增加一层固定 Agent 工作流更值得投入。
