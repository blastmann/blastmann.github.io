今天最值得看

1. browser-agent-verifier：真实浏览器显示成功，后端可能根本没有写入（11/11 新仓库）

发生了什么：braylo-ai/browser-agent-verifier 于 2026-11-11 07:39（北京时间）创建，提供 Playwright + 真实 Chrome + SQLite 的可重置测试网站，覆盖提交表单、下单和设置。它刻意注入“显示成功但没有保存”“已保存却返回 503”“点击被吞”“按钮延迟出现”等故障，比较不重试、原地重试和分段恢复三种策略。

为什么重要：Agent 看到成功 Toast 并不等于任务真的完成；尤其“写入成功但响应失败”之后的盲目重试，可能造成重复订单。项目的独立 Verifier 不采信 Agent 当前页面，而是通过独立浏览器 Context + 只读 API检查真实后端状态、写入是否恰好一次；由测试 Harness 读取 SQLite 作为判定基准。

证据与成熟度：README 声明 2026-11-10 的真实 Chrome 测试 19/19 通过；原计划 135 个 Episode 的基准测试因宿主机器过载中断，没有完整的成功率/误报率统计；Agent 是脚本计划而非 LLM 自主规划，故只能证明验证机制，不代表真实模型能力。工程启发：Browser Self-Improvement 应先引入与 Agent 操作页面隔离的独立验收者，并明确检查 exactly-once 状态，特别适合表单、支付、账号设置、发布流程。原始说明和限制。

2. Chrome DevTools MCP：页面级网络 Mock 正式合并（11/11 00:33）

发生了什么：ChromeDevTools/chrome-devtools-mcp #3384 于 2026-11-11 00:33（北京时间）合并。增加 mock_network / remove_network_mock，可按 URL Pattern 和资源类型用本地文件替换 Chrome 页面的网络响应；规则支持统计命中次数、匹配检查和文件失效报告。

为什么重要：Agent 可在不改线上服务的情况下，对失败的 JS、CSS、接口响应或网络资源做可重复实验。默认不开放，需显式开启 --categoryNetworkMocks；Mock 生效时禁用页面缓存并拦截请求，因此性能 Trace 与 Lighthouse 会附带测量警告；录制 Trace 时也不能任意改规则。

证据与边界：PR 作者报告 1,863 测试通过、3 跳过，含真实 Chrome 集成测试。已合并的是本地文件响应替换；上游 URL 代理与 abort/allow-origin 仍由后续 PR #3420 / #3421 继续推进。工程启发：将网络故障注入作为 Agent 可发现工具，但必须把测试污染标记进证据，避免把 Mock 下的性能收益当成真实线上改善。

3. Playwright：失败 CI 自动交给 Bot 判断是否由当前 PR 引入（11/11 04:45 已合并）

发生了什么：microsoft/playwright #44042 于 2026-11-11 04:45（北京时间）合并。当 PR 测试报告有失败，且作者具备仓库写权限或是 Bot 时，create_test_report.yml 的 triage Job 会把PR 和失败 Run交给 Playwright Bot；Bot 会在 PR 中留言判断该 PR 是否造成失败。与此同时移除旧的重复 Triage Workflow 和 Bot Voice Guide。

为什么重要：这是有真实触发信号的工程 Agent 任务连接，不是抽象的“让 AI 自我改进”。CI 失败本身是 Observe；由 Bot 结合 PR 判断归因是 Diagnose，但本次没有证明它会自动修复、独立验证或自动吸收经验。

工程启发：浏览器团队可提供 {failingRun, changedFiles, revision, flakyHistory, platform, artifacts} 的标准证据入口，让 Agent 自主选择 bisect、日志对照或复现工具；随后通过独立验证决定是否接纳修改，而不是硬编码修复流程。

4. Boltz2 WebGPU：在浏览器内完成蛋白质—配体联合折叠与打分（11/10 新仓库）

发生了什么：pablo-arantes/boltz2-webgpu 于 2026-11-10 22:39（北京时间）创建，基于 LocalFold 移植 Boltz-2。在 WebGPU 页面内输入蛋白质序列和多个 SMILES 配体，逐一联合折叠、预测两种亲和力指标、排序、比较三维姿态，输出 CSV/结构和图表。页面静态托管，无需应用服务器。首次需要下载约 365 MiB 结构权重 + 6.5 MiB 亲和力模块；选择可选 MSA 搜索时会把序列发往外部 ColabFold API。

为什么重要：体现浏览器端侧 GPU 可以承载复杂科学推理，但更值得研究的是完整模型分发、CacheStorage、不同模型分支、数值对照和失败留证，而不是页面能否展示 3D 结果。

证据与成熟度：作者将移植结果与上游 PyTorch Boltz-2比较，六个配体的两种排序相关系数分别报告为 +1.000 与 +0.886；但使用的 20 个扩散步与上游 200 步不同，没有用真实实验亲和力数据验证预测准确性。作者也列出修正后的错误、仍然存在的数值偏差和许可证注意事项。工程启发：端侧 AI 推理需要区分“和参考实现一致”“真正预测正确”“设备上跑得快”三项不同指标。原始测量记录。

5. Playwright Extension：明确 Tab 所有权和可恢复分组（11/11 待合并）

发生了什么：microsoft/playwright #44047 于 2026-11-11 07:54（北京时间）提交，截至观察时尚未合并。候选方案在扩展中维护客户端与 Tab 的 Owner 映射，禁止客户端操作不属于自己的 Tab，并拒绝修改 Cookie 与浏览器全局权限等跨会话状态；用户可以选择授权整个 Tab Group 或指定标签，断开后原分组保留供下一个客户端接管。

为什么重要：真实 Profile 多 Agent 共用一个浏览器时，资源隔离不能只按对话 Session 分开；必须明确浏览器标签、登录态和全局权限的归属。工程启发：可以为 AI Native Browser 设计可撤销的 TabLease/Owner，并在跨 Agent 接管时生成审计回执。但这是提案，不能当成 Playwright 正式发布的功能。

浏览器技术

Chrome DevTools MCP 的 Network Mock 是本期最值得复用的浏览器底层变化。其最大价值不是新增一个按钮，而是为 Agent 提供受控替换网络资源、运行同样的页面任务、比较 Trace 与错误输出的基础工具。对 Chromium 端可以直接做网络/媒体资源降级实验；迁移 WebKit/Firefox 则需要等价的网络拦截与隔离测试接口。

Google 在 11 月 9 日的官方更新 中将 Chrome 桌面稳定通道推进到 157.0.8103.50/.51（Windows/macOS）和 157.0.8103.50（Linux）；这是两天前的更新，不是今天新功能。本次未确认 Chrome、WebKit、Firefox、Edge、Opera、Brave 在过去 24 小时有更高价值且日期可靠的官方架构公告，不用普通版本公告凑头条。

端侧 AI

Boltz2 WebGPU 和新兴 Kronos WebGPU 同时显示，越来越多复杂推理任务被移到静态网页：权重在线下载并本地缓存、GPU 或 WASM 执行、可选云端服务增强。但“不上传推理内容”必须具体到每项网络调用；例如 Boltz2 的可选 MSA 会传输蛋白质序列。

LiteRT-LM #4517 于 11 月 11 日 09:10（北京时间）提交，提出移除 WebGPU Sampler Readback 中约 4ms 的计时器停顿。它是尚未合并的候选补丁，不是已测得的整机生成速度改善。建议继续观察实际浏览器 Profile、每 Token 同步次数和发布后的 Safari/Android 数据。

浏览器 × AI

Playwright 的 Tab Owner 提案、dsh-agent-browser 的显式分享标签，以及 pi-browser-handoff 的受限登录态移交，围绕同一个真实需求：Agent 应可在用户熟悉的浏览器中工作，但不能因为拥有 MCP 连接就自动拥有所有标签和全局权限。

针对自己搭建的 Browser Agent，可把 TabOwnership、CredentialScope、ActionReceipt 拆成独立能力。Cookie 等敏感数据不返回给模型；一次浏览器操作也需能明确识别执行者、站点范围和实际效果。

工程建议：优先建设两个自由调用的工具：ObserveRun 留下浏览器 Revision、Target/Frame、输入、网络 Trace、Console 与实际结果；VerifyEffect 在不同 Session 或后端独立只读入口检查成功条件和是否发生重复写入。Agent 自主决定何时使用，不预设固定步骤；但任何候选修改或 Skill 的晋级由独立证据决定。

边界：本期没有证据表明 Chromium、WebKit 或 Firefox 内核已经建立完整的自动 Observe→Diagnose→Improve→Verify→Canary→Learn 生产闭环。

今天的一个判断

Browser Self-Improvement 的关键分界线，正在从“Agent 是否宣称完成”转向“独立环境能否验证真实效果”。 如果把失败 CI、网络注入、浏览器操作回执和后端状态验证接入同一套可探索工具环境，就能先形成可信的局部改进，再决定何时自动提交、推广或回退。对端侧 AI 也一样：参考模型一致、任务准确和性能改善必须分别验证。
