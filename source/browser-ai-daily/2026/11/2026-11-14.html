1. Firefox：近 2500 万真实设备数据，推动抗指纹方案从猜测走向数据驱动（11/10 官方研究，补推）

发生了什么：Mozilla、University of Toronto 和 UC San Diego 的研究在 11 月 10 日正式解读 CCS 2026 论文《野外浏览器指纹的大规模测量与真实世界缓解》。研究通过专用 user-characteristics Telemetry 和 Oblivious HTTP 收集约 2500 万 Firefox 用户的设备特征，并模拟 Fingerprint Pro、Signifyd、Akamai 的实际指纹信号组合。作者公开聚合数据、分析代码和浏览器测试页，原始个人级数据已经删除。

技术上新在哪里：不是再列举几十种可被追踪的 API，而是利用大规模真实分布找出少数真正让用户变得独特的信号组合，用用户被分到多大的群组来衡量保护效果，并按操作系统分别设计 API 值标准化与随机化。例如限制可用屏幕区域信息、把处理器数量规整到常见档位，并减少 Android 上图像、音频和数学计算中的可区分差异。

证据：在作者建模的 Fingerprint Pro 信号集上，唯一指纹用户比例从 75.7% 降为 46.8%；Signifyd 从 60.9% 降至 38.5%；Akamai 从 18.2% 降至 9.0%。这些是研究所模拟的识别能力变化，不是实际所有追踪商的检测率；有关防护早已进入 Firefox 143 等版本，并非 11 月 10 日才上线，也不能宣称指纹追踪被彻底解决。

工程启发：浏览器隐私机制的优化对象应该是用户群体的可识别性，而非单个 API 的信息熵。建立按 OS 分组的 Fingerprintability 基线、网站兼容性回归、灰度与遥测对照，适合迁移到 Chromium/WebKit/Firefox。值得深入研究：高。来源：Mozilla 原始技术文章、研究站（聚合数据、代码、测试）。

2. WebKit：让性能分析认识真正的 GPU 合成帧，而不是误判主线程循环（11/10 周报，补推）

发生了什么：Igalia 的 WebKitGTK/WPE 工程在 11 月 10 日汇总了重要架构调整。新的 Skia Compositor 已于 9 月作为 GTK/WPE 默认合成器，此次正式移除构建旧 TextureMapper 的支持；更值得看的是 webkit-sysprof 把“两个主线程 LayerTree 更新之间算一帧”的旧统计模型替换为真正的 Compositor Composition 事件，并增加 timeline 命令，把主线程和 ThreadedCompositor 画在同一时间线上。

技术上新在哪里：旧采样可能完全忽略合成线程独立渲染的加速动画帧。官方改动举例中，旧分析把真实 60 FPS 的页面错误推算为 3.69 FPS。新工具会将绘制更新与展示该结果的 Composition 对齐，并拆分阶段延迟。这不仅是一个统计修正，而是改变了判断掉帧和优化收益的观察模型。

工程启发：做浏览器端自动性能诊断，必须合并 Main Thread、Raster/GPU、Compositor 的 Frame ID 与事件，不能把 JS/DOM 更新间隔直接当成屏幕帧率；多平台 Android WebView、WKWebView、Chromium 也应检查类似盲点。状态：WebKit 源码已提交，作用范围主要是 WebKitGTK/WPE 的调试与合成器链路，不等于 Safari iOS 已切换 Skia。值得实测：高。来源：Igalia WebKit #85、合成器帧报告原始 Commit、移除 TextureMapper 构建支持的 Commit。

3. Safari 登陆 Apple HomeView：从鼠标优先的网页转向语音、方形小屏与结构化内容（11/13 官方发布）

发生了什么：WebKit 11 月 13 日宣布 Safari 进入 Apple HomeView 这一新终端。设备采用 7 英寸方形显示屏，用户主要通过语音或触控操作。Safari 可读取网页使用 schema.org/Recipe 的 JSON-LD，提供适合料理场景的分步骤内容呈现。官方还提醒：HomeView 可能使用 iOS User-Agent，但它并不是手机；开发者应该做能力检测而不是按 UA 字符串判断设备。

技术新颖性判断：这是新平台、新输入模式和已有语义标准的具体产品级结合，而不是新 JS API 或新的大模型架构。对 AI Native Browser 的价值是“语义信息 + 语音指令 + 内容重组”的产品路径，不能由此断言 Safari 提供了新的通用 Browser Agent API。

工程启发：建议测试语义化可点击元素、aria-label、短视口与方屏布局、WebVTT、Recipe JSON-LD；用 Safari Responsive Design Mode 的 448×364 视口复现部分布局问题，真实语音行为仍需设备验收。值得研究：中高（多模态浏览器体验）。来源：WebKit 官方文章（11/13）。

端侧 AI

过去 24 小时没有经确认足够新颖的浏览器端 LLM Runtime 正式算法发布。值得持续跟踪的是 WGSL Subgroup/Workgroup Matrix 的标准化讨论，以及 Bindless 资源调试信息：前者有潜力减少本地矩阵计算的手写 Shader 成本，后者改善诊断，但都尚未落地，不能作为性能收益报道。

浏览器 × AI

Safari HomeView 的结构化网页识别说明“网页语义先行，语音交互和内容再组织在上层”是一条现实产品路径。对于 Browser Agent，页面中的真实按钮、标签、Recipe 结构、Caption 比纯坐标点击更可靠，但本期没有证据证明 HomeView 提供了对任意网站的自主 Agent 操作。避免把语音 UI 宣传误报为 Browser Agent 技术突破。

今天的一个判断

影响浏览器技术路线的未必是一个全新浏览器或 Agent 项目。Mozilla 用真实群体数据证明哪些指纹信号值得保护；WebKit 纠正了多线程合成器中的观测盲区。两者共同指向：技术创新要能改变底层机制，并通过独立、可解释的数据证明改变有效。相比之下，“新 MCP 封装”和“今天刚创建的仓库”应自动降级，除非能展示新的算法、架构或可复现的突破。
