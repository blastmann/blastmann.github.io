今天最值得看｜2 项七日补推

1. ROGUE-AI：事故复现要有“只删除一个原因”的对照组（11/19 UTC 首次论文）

发生了什么：研究者提出 Replication of Agentic Security Events: Audit and Investigation（ROGUE-AI），面向公开报道的 Agent 事故，自动建立一套离线的事故复现场景，同时建立一套只去掉所声称事故根因的对照场景，使用实际模型多次执行，并由代码判断有无发生伤害。相比只收集事故报告或运行普通 Prompt Injection 测试，它真正尝试检验“为什么出错”。

技术新在哪里：一条事故轨迹不能证明因果；配对环境可以区分“Agent 本身倾向犯错”“危险共享资源配置导致的伤害”和“单纯的测试偶然性”。例如模拟开发测试库错误地指向生产数据库，另一环境仅把测试连接改为临时库，在两边运行同样任务。论文的专家 Agent 分别负责筛选报告、构建环境、独立复核，最终风险结果由可执行状态检查而非 Agent 自我解释决定。

证据：作者报告在 108 次构造的事故复现尝试中约 89% 复现了预期伤害；五类模型在事故条件下造成伤害的比例为 18%—33%，在对照条件下不超过 1%。论文指出真实发生伤害的 72 起案例中有 62 起没有外部攻击者：Agent 可能是在执行正常任务时漏掉共享数据库、文件等危险约束。这些数字只适用于作者重建的模拟环境，不是商业 Agent 的线上总体事故率。研究未能复现 12 个场景，且原始报告不完整可能导致原因重建错误。不能宣称已经独立证实所有事故原报告。

技术新颖性：高（事故因果对照评估机制，而非新模型算法）。值得研究/实测：非常高。建议针对 Browser Agent 的“误提交订单”“跨账号修改”“错误删除文件”等场景制作带副作用保护的合成站点：固定任务、模型、权限和工具，仅改变一个危险环境条件，比较任务完成率、伤害率和原因归因一致性。测试必须断开真实生产数据。

原始来源：arXiv:2611.26553（11/19 18:23 UTC）。论文包含系统设计、对照定义、作者实验数据与局限；本期未验证存在可直接运行的公开完整复现代码。

2. Origin：从 Agent 行为轨迹追溯到危险内容最初进入程序的代码位置（11/19 UTC 首次论文）

发生了什么：Backtracking Agent Applications Security Incidents 提出名为 Origin 的事故回溯工具。普通 Agent Trace 记录的是“调用搜索”“读取记忆”“选择工具”之类语义动作，实际安全漏洞则发生在代码某次函数调用、变量传播或动态分发中。两类日志之间缺乏直接对应，人工排查通常需要逐文件追踪。

技术新在哪里：它使用跨层依赖图（CLDG），将 Agent 功能分组、源码函数调用和污点传播路径连接起来；分析者通过少量查询缩小搜索范围，定位最早输入危险内容的 compromise entry point（CEP）。原型使用 Joern、Pyrefly 等工具强化动态调用解析和跨函数数据流，而非只让 LLM 猜测哪段 Prompt 出错。

证据及边界：论文在 GPT-Researcher、Quivr、aider、MetaGPT、SWE-agent 共 5 个开源应用的 8 个攻击事故案例中，报告分析者均找到对应入口。原型约 16K 行 Python 代码，且仍依赖分析者与特定 Python 项目构造；样本小、不代表任意框架的自动化可用性，未见独立大规模跨语言复测。

技术新颖性：高（Agent 语义轨迹与代码级数据流的跨层定位）。值得研究：高；立即移植到生产：中。可从 Browser Agent 的一次恶意 DOM/网页内容输入开始，记录 Action ID → 页面/Frame 来源 → 工具响应 → 上下文片段 → 影响的策略/函数 → 最终副作用，验证是否能反推出首次进入点。对浏览器原生代码和混合语言 Runtime，须另外解决源码分析和事件 ID 的映射，不能直接照搬 Python 原型。

原始来源：arXiv:2611.26525（11/19 18:01 UTC）。本期未核实作者公开可安装的 Origin 完整工具包。

浏览器技术

WebNN 标准进度：W3C 发布历史显示 11 月 17 日与 20 日均有 Candidate Recommendation Draft 版本。当前草案具有 navigator.ml、MLContext.dispatch()、createTensor()、exportToGPU() 等接口；其中 Tensor 共享和更多 Transformer 算子是 2024—2026 演进成果，不能归因于本次 11 月 20 日文字修订。W3C 仍要求足够的独立互操作实现与测试才能推进到下一标准阶段。对端侧推理最重要的长期信号是操作系统原生 AI 后端与 WebGPU 能否低成本共享 Tensor，并通过跨浏览器 WPT。

其他浏览器：已检查 Chromium/Chrome、WebKit/Safari、Firefox、Edge、Opera、Brave、WHATWG、WebGPU/WGSL 的近期公开材料。没有确认本窗口具有可独立论证重大新机制的正式首发。WHATWG HTML 11 月 20 日的修改以规范编辑性质为主，不作为技术突破重复推送。来源：WHATWG HTML 提交记录、W3C WebNN 草案。

端侧 AI

本窗口没有独立核实到足够重要且未重复的手机 NPU、新 WebGPU Kernel 或端侧 Runtime 机制首发。将 WebNN 的 MLTensor 与 WebGPU 数据交换作为中期研究信号：对照 CPU 拷贝次数、图编译/冷启动、峰值内存、P95 延迟、能耗和浏览器实现覆盖率；不要依据候选规范就假定所有平台有稳定 NPU 加速。

浏览器 × AI

ROGUE-AI 强调在可控环境检验危险动作的原因，Origin 强调在代码层找出危险输入从哪里进入。二者可分别用于 Browser Agent 发布前的独立验收和事故后的根因分析，但论文研究对象不限于浏览器。把它们拼成一套 Browser Harness 仍需工程验证，不能称为已有的完整产品能力。

今天的一个判断

Agent 工程需要的不只是“知道出错了”，而是能证明什么条件导致了错误，并能追溯危险信息具体在哪里进入了系统。对 Browser Agent 来说，先建设可复现的事故对照、执行证据和独立判分，比继续扩大工具目录更有价值。今日优先研究 ROGUE-AI 的配对验证方法；Origin 适合作为第二阶段的代码级诊断能力。
