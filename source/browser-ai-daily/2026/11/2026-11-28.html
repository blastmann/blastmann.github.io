今天最值得看

1. TimeTravelContainer：让 Agent 的运行环境像代码一样分叉

NVIDIA Research 的 TimeTravelContainer（TTC） 于 11/24 UTC 首次提交论文。基于 gVisor 用户态内核，TTC 在同一运行环境中复制进程、线程、文件描述符、文件系统和受支持的内部网络状态；多个分支共享未修改的内存页，首次写入时才复制 4 KiB 页面。与 Git worktree 只处理文件、普通容器重启丢失内存状态不同，它支持保留已初始化工具的运行状态，进行并行尝试、暂停恢复及按需跨节点迁移。

这些是 EDA 工具实验，不是浏览器任务测试；固定工具调用回放不含 LLM 推理耗时。注意内存节省取决于分支写入及状态差异。完整论文、Apache-2.0 源码。仓库创建于 10/22（GitHub 元数据），本周新进展是论文及实验证据，而非新建仓库。

技术新颖性：高；值得实测：非常高；成熟度：开源研究原型。在 Linux 上可无需 KVM 或 root 运行；Apple Silicon 后端使用 Hypervisor.framework，Windows 经 WSL 2，运行的均是 Linux 环境，不代表原生 macOS/iOS 进程可克隆。仓库描述了 Vulkan/CUDA 与 Android 示例，但不是完整 Agent 安全边界。浏览器 GPU、跨容器服务、外部 TCP/TLS 连接与远端副作用需另行验证。

工程启发：在测试站点中启动 Chromium，加载页面并建立本地状态后分叉多个任务，测量 clone 延迟、RSS/PSS、页面及存储隔离、渲染正确性和最终任务成功率；禁止将外部真实网站操作当成可自动回滚。

2. NVIDIA × Reactor：利用 Attention 寄存器生命周期消除 GPU 流水线空档

11/25 技术文章 对 SageAttention3 的 NVFP4 Kernel 进行重新调度。原实现每个 N128 tile 顺序计算 QK、Softmax/量化、PV，寄存器用量已占 SM 容量约 95.3%，无法直接额外分配完整 tile。新实现将 score tile 拆为两个 N64 slot，在前半部分量化完成后复用已无后续用途的 score 寄存器，提前计算下一 tile 的 QK；保持 N128 的 K/V 读取及完整 tile 的在线 Softmax 状态更新。

Reactor 在 RTX PRO 6000 Blackwell 96 GB 上报告核心 Kernel 1.17–1.64× 加速；整模型相对 BF16 的延迟改善因场景而异，例如 LongLive 32 帧 5.13→4.79 s，OmniDreams 长序列约 15%。整模型对照同时包含量化和其他路径差异，不能归因于寄存器调度；厂商及合作方实验，非独立复测，也不代表手机 GPU 或 WebGPU 可直接获得收益。

技术新颖性：中高；值得研究：高；成熟度：合作方已集成生产服务的报告。区别于此前 Shifter Quantization 的数值表示改造，此处优化的是寄存器存活区间和指令调度。建议用 GPU profiler 观察 Tensor Core 空档、寄存器压力、占用率及端到端延迟，再判断能否迁移其他后端。

浏览器 × AI

TTC 为 Browser Agent 的探索提供另一种可能：把模型上下文的分支与浏览器内部运行状态的分支一一对应。相比重开 Tab 并重放操作，可能节省页面加载和会话准备成本。它目前没有论文级浏览器验证，外部服务状态也不会自动回滚。优先使用可重置的模拟网站和独立结果检查器做实验。

Browser Self-Improvement

ReproCue：从 AI 代码审查的文字怀疑生成可验证复现证据

11/25 UTC 提交的论文 先重放历史内核缺陷，从成功案例提取各子系统的复现状态机（FSM），再针对新审查报告按执行结果调整测试与运行环境。100 条近期 Sashiko 审查中，作者报告 52 个触发崩溃的案例，其中 49 个与原报告匹配；重实现 K-Repro 为 10，SyzDirect 为 9。49 个匹配案例提交维护者后，34 个被确认并修复（69.4% 是 34/49，不是全部 100 个报告的确认率）。对照的 Sashiko 纯文本确认率 9.3% 来自另一组邮件采样，非严格随机 A/B。

闭环证据：Observe（审查报告、历史复现）→ Diagnose（状态机及环境适配）→ Improve（生成或修正复现测试，而非自动修复内核）→ Verify（执行证据与报告匹配、人工复核）→ Learn（从历史成功复现提炼 FSM）；尚无持续自动回流或浏览器生产 Canary 证据。论文方法和完整结果。技术新颖性：中高；值得研究：高。可迁移到 Chromium/WebKit/Firefox 的 Crash/WPT/Trace 验证：必须核对原始故障签名，不以任意崩溃或 LLM 自评为通过条件。没有复现不能直接认定报告错误。

今天的一个判断

Agent 的自主探索成本不仅取决于模型 Token，还取决于环境是否能低成本分叉，以及每个分支能否产生可信、可重复的结果。 TTC 降低尝试成本，ReproCue 改善验证证据，两者可以启发独立探索环境和 Verifier 的设计，但并非已集成或验证的 Browser RSI 系统。建议优先做本地浏览器状态分叉与隔离对照实验，再接入实际优化目标。
