今天最值得看

Self-Improvement

Warp：用真实工程反馈持续改 Skill，而不是直接让 Agent 改自己

Warp 的模式是 base skill + improver skill：周期性读取 GitHub issues / PR 等人类反馈，提出最小 Skill 修改，通过 PR / code review 后合入，并在下一轮任务中复用。

关键原则：可验证领域先建立 verification harness；难以自动验证的领域依赖领域专家反馈。

Warp / Claude Blog

Chrome 152

CPU Performance API：浏览器开始暴露设备能力层级

可与 Compute Pressure API 组合，让 Web App 根据设备能力和实时压力调整计算负载。

Browser AI 启发：Local/Cloud 路由可以综合 capability tier、pressure、WebGPU、memory 和 network。

CAFE

Actor 与 Critic 都需要共同演化

CAFE 让同一模型在 Search Agent 与 critic 角色间交替，联合优化什么时候请求反馈、反馈如何修正轨迹。

启发：Verifier / Judge 也会过时，Self-Improvement 不能只升级执行 Agent。

CAFE 论文

Metaⁿ

固定 Improvement Protocol，比让 Agent 递归改改进逻辑更安全

Metaⁿ 通过固定 meta-operation 读取历史 solver traces/code，生成策略预处理和 helper tool 层，但不让系统递归改写自身改进协议。

今天的一个判断

今天在 Memory Hygiene、Executable Learning 后，再补一层：Reviewable Improvement。

Self-Improvement ≠ Self-Modifying Code。最现实的自主修改范围应该逐步扩大：

Skill → Test → Benchmark → Config → Small Patch → Core Patch

先让做浏览器工程的 Agent 自我改进，再让浏览器本身自我改进。
