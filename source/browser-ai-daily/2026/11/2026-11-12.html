今天最值得看

1. Lightpanda：Agent 保存脚本之前先无模型重放验证（待合并）

发生了什么：Lightpanda #4588 于 11 月 11 日 23:06（北京时间）提交，仍是开放 PR、未合并。此前 agent --task ... --save 直接保存模型生成的脚本，选择器一旦是模型凭空猜测的，后续执行可能得到空数组。维护者以 Craigslist 找自行车任务作例子，称此前约一半脚本回放返回 []。

改动与价值：新方案仅对只读脚本执行一次不调用模型的重放；若失败、超时（60 秒）或返回空值，再让 Agent 读取真实页面，最多执行一次受限修订，并再次重放。工具表中新增 replaySafe，执行层另加 read_only 拒绝写操作。含点击、提交等副作用的脚本不自动重放，避免重复下单或重复提交。

工程启发：这是“Observe（真实页面）→ Diagnose（空结果）→ Improve（重新生成）→ Verify（独立脚本重放）”的局部闭环；还缺合并、长期回归和 Learn。浏览器测试工具可以把只读脚本自动重放、写操作交独立状态验证设为两条不同的晋级路径。PR 描述的是提交者实验，不是正式发布的成功率提升。

2. Chrome DevTools MCP 1.13.0 正式发布：Network Mock 与 Logpoint

发生了什么：Chrome DevTools MCP v1.13.0 于 2026-11-11 20:40（北京时间）正式发布，Release Notes 确认新增 Logpoint、页面级网络响应 Mock，以及从上游 URL 提供替换响应。此前日报报道的是相关 PR 已合并，这次首次可以确认正式 Release 已交付。

为什么重要：Agent 可以在不修改线上代码的情况下替换 JS、CSS、接口响应或调试特定行为，Logpoint 可在运行时记录证据而非反复修改源码。后续 #3421 又于 11 月 12 日 01:15（北京时间）合并“阻断请求”和允许指定 Access-Control-Allow-Origin 的能力，但该合并发生在 1.13.0 发布之后，不应误称已包含在 1.13.0。PR 自述 1955 测试通过、3 跳过，含真实 Chrome 验证。

工程启发：将 Network Mock 视作受控测试环境，记录 Mock 是否开启、替换规则、命中数以及对缓存和性能测量的影响。默认功能关闭，需要显式使用 --categoryNetworkMocks；不能把被 Mock 改写的 Lighthouse/Trace 当成生产真实性能。

3. LiteRT-LM：新增可复用的结构化模型决策接口（已合并）

发生了什么：LiteRT-LM #4549 于 11 月 12 日 08:26（北京时间）合并，新增 DecisionEngine 与 LlmDecisionEngine。它通过现有 Engine 和 Session，对 A–Z 候选选项使用 RunTextScoring，在克隆 Session 中进行评分，可与现有 Conversation 共享 Engine，也可以自己创建 Engine。

为什么重要：端侧模型服务不必把所有决策实现为长文本生成，诸如是否需要检索、要不要升级权限、选择哪项工具可用更清晰的受约束分类接口实现。但这只是核心接口已合并，不等于浏览器端已有稳定产品 API，也没有公开证明决策校准或延迟收益。另有 #4548 合并了 LiteRT-LM Web 聊天 Demo 的独立静态构建能力。

工程启发：AI Native Browser 可把“模型提出动作”和“执行系统实际授权”分离：决策接口负责有限选项评分，浏览器运行时负责权限检查、动作回执和结果验证。

4. browser-mcp-debug：同一 Chrome 中并用 Playwright MCP、DevTools MCP 和 VS Code 调试

发生了什么：mm-lab-dev/browser-mcp-debug 创建于 11 月 11 日 17:01（北京时间），提供 VS Code 调试扩展：在专用持久化 Chrome Profile 中启动项目，允许 Playwright MCP、Chrome DevTools MCP 与 VS Code Debugger 共用同一浏览器。支持 Remote-SSH：代码与服务器可在远端，Chrome 和 MCP 保留在本机。调试结束时一起停止后台进程。

为什么重要：它实际缓解了 AI Coding 中“工具各自打开一个浏览器、登录态与页面不一致”的问题。特别适合前端调试、错误复现和自动截图、Trace 联合采集。

成熟度与工程启发：新仓库，README 和 VSIX 发布说明可核实，尚无独立生产稳定性数据；当前专门支持 Chrome。可借鉴其一个调试 Session 对应一个浏览器实例及一套工具连接的生命周期，避免 Agent 进程和浏览器 Context 泄漏。

5. Chrome DevTools MCP 正在准备进入 devtools-frontend 原生构建体系（待合并）

发生了什么：Chrome DevTools MCP #3465 于 11 月 11 日 22:35（北京时间）提出将工具的测试路径、GN 构建依赖、Chrome for Testing 路径以及 CI Runner 适配 devtools-frontend/for_agents 的源码树与输出目录，说明维护者正在为未来的合并做准备。

为什么重要：若后续落地，Browser Agent 工具与 DevTools 前端可能共享更多测试与构建基础设施，减少独立 MCP 运行环境和 Chromium 调试版本之间的差异。但当前仅为准备性 PR，尚未证实 DevTools MCP 已迁入主仓库。

工程启发：浏览器自身的 DevTools/Agent 工具应该共用可复现的构建、测试工件与 Chrome Revision；不要把工具层长期看成和浏览器版本无关的外部脚本。

端侧 AI

Google DecisionEngine 体现了本地模型从“生成一段话”扩展到“给有限备选项评分”的工程接口，模型能力与运行时授权需要分别测量。另外，StatefulDecoder / WhisperDecoder #4536 提出对带时间戳的音频解码加入有状态缓存；作者称约 2 倍推理提升，截至观察时仍待合并且无独立设备测量。静态 Web Demo 构建 已合并，更便于离线静态托管实验，但不是模型推理性能的证明。

工程启发：端侧 Runtime 的对照需要区分模型本身的决策质量、GPU/CPU 延迟、Session 安全、模型加载和安装后的离线可用性。不能把某个 Decoder 的局部耗时推断成完整 Android / iOS 应用提升。

浏览器 × AI

这次新出现的 browser-mcp-debug、chrome-use 和 browser-mcp 展示三种不同的浏览器连接方式：专用 Debug Session、多步骤 CDP CLI、真实 Profile 经远程 Relay 暴露 MCP。应统一比较它们是否提供可撤销的连接、可判定的目标、对用户登录态的保护、操作后的独立状态回读以及进程清理，而不是单纯比较 MCP 工具数量。

Chrome DevTools MCP 的新 Release 和原生构建准备也说明，Browser Agent 运行时与 DevTools 测试、浏览器版本号之间的联系将更紧密。

WebKit #80585（待合并）识别 Mock Geo 数据跨测试泄漏 → 修正重置逻辑的候选补丁可用于改善 Harness 的测试隔离；目前未合并，不存在自动 Improve→Canary→Learn 证据

优先可迁移的方法：把任务分成只读操作和可能产生副作用的操作。只读脚本可在新 Session 重放并比较产出；会发消息、修改设置、支付或提交的脚本不能无条件重放，应由只读后端验收入口、测试沙箱或人工审查确认。每次验证需记录浏览器版本、数据环境、输出和失败原因，再决定是否把修改晋级为可复用 Skill。这比让 Agent 按固定流程跑更容易形成可自由探索且可信的环境。

结论边界：本期没有证据证明 Chromium、WebKit 或 Firefox 已经实现端到端 Observe → Diagnose → Improve → Verify → Canary → Learn 的自动持续改进。

今天的一个判断

Agent 能否学会一套浏览器操作，已不再是最难的部分；更重要的是，它敢不敢在保存经验之前重放、会不会把不可信的空结果当成成功，以及如何避免对真实账号重复执行有副作用的动作。 Lightpanda 的只读 Replay Gate、DevTools MCP 的可控网络环境、Playwright 的隔离测试、Browser Harness 的独立复演，正在为这套机制提供可组合的基础能力。
