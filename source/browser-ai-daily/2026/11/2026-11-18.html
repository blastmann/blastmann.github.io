1. Microsoft Edge for Business：每个 Browser Agent 都有单独的企业身份与受控窗口（11/17 官方发布）

发生了什么：微软 11 月 17 日 Ignite 技术公告中公布 Managed Agent Browsing，允许 Microsoft 及其他提供商的 Agent 进入企业统一管理的 Edge。每个 Agent 在独立窗口中运行，携带自己的 Microsoft Entra agent identity，但仍受用户现有授权和组织策略限制。状态：受控 Agent Browsing 是 Preview，要求 Microsoft 365 E5；Cowork 中 Agent 浏览能力则宣称已 GA，且涉及 Copilot 许可与按量计费。

技术究竟新在哪里：不同于让多个 Agent 共用 CDP Session 或为 Tab 添加所有权标识，微软把 Agent 身份与浏览器访问策略绑定，成为企业身份系统可管理的执行主体。这给 Browser Runtime 提出可迁移的设计：Agent 身份、代表哪个用户、允许访问哪些网站/数据、操作审计，应由浏览器和权限基础设施承载，而非依靠 Prompt。计划与现状分开：Agent 365 集中管理、Entra 日志识别代理操作，以及阻断/隔离有风险 Agent 仍被描述为未来愿景，不能算已经上线。

可验证证据：微软同时宣称其常见网站动作优化在早期内部测试中平均节约约 30% Token，但未给出任务集、基线与误差。该优化仍处研发阶段，不能直接当作正式产品表现。技术新颖性：中高（浏览器和企业身份集成）；值得研究/实测：高。建议使用一个只读企业 Web App，在同样任务下比较多 Agent 身份隔离、权限继承、审计回执、失败恢复及 Token 消耗。来源：微软 Edge 官方 Ignite 2026 文章（11/17）。

2. Cloudflare Kitesurf：无需 Chromium 容器的 Workers/WASM 浏览器引擎正式开源（11/13，七日补推）

发生了什么：Cloudflare 11 月 13 日将已在今年 8 月首次介绍的 Kitesurf 引擎以 Apache-2.0 开源。这是开源里程碑，不是引擎 11/13 才首次发明。Kitesurf 在 Cloudflare Workers 中解析 HTML、计算 CSS、执行页面 JavaScript 并绘制截图，无需启动 Chrome/Chromium 容器，仍对外提供 CDP 接口以复用 Puppeteer 等客户端。

技术究竟新在哪里：不只是套一层代理：它把浏览器内核拆分为 Engine、PageScript、PageRenderer；由 Rust/WASM 的 Blitz 实现 DOM、布局及绘制，Stylo 处理 CSS，Boa 在无法使用 Dynamic Workers 运行 JS 时作备用，结合 Linebender 字体/2D 和 Krilla PDF。核心选择是把浏览器运行环境转成可在 Serverless Isolate 中按需扩展的组件化 Runtime。

证据、风险与成熟度：Cloudflare 原始代码与构建说明可查，项目明确标为实验性，正在改善 WPT 兼容性；它不是已具备 Chromium 全站兼容性的替代品。远端部署需 Workers Paid（Dynamic Workers）；仓库特别警告本地 workerd 不是经过加固的不可信网页执行沙箱。README 还记录了长时间连续导航在垃圾回收方面的内存边界：一项作者测试中，未暴露 GC 时约 300 页后 OOM，启用显式 GC 后 5 个并发连接累计 940 页、内存低于 4 GB。这是作者指定负载实验，非对 Chromium 的独立公平 Benchmark。

技术新颖性：高（新的轻量浏览器架构组合）；值得实测：非常高。建议同样脚本分别用 Kitesurf、Chromium、Lightpanda 跑复杂 JS、SPA、多 iframe、媒体、下载上传、跨站身份；记录 WPT 子集、成功率、P95 延迟、内存与故障分类。来源：Cloudflare 官方文章（11/13）、开源仓库及构建说明。

3. WebArena-Pro：把音频/视频与跨站真实业务纳入可复测 Browser Agent 基准（11/13，七日补推）

发生了什么：研究团队在 11 月 13 日提交 WebArena-Pro 论文，覆盖 20 个自行部署的 Web 应用、6 类业务。论文报告的核心测试集有 300 个任务，其中 96 个跨网站任务、79 个需要处理音频/视频；目前仓库 README 展示400 个任务（100 dev + 300 test），两种计数口径不冲突。

技术究竟新在哪里：传统网页 Agent 评测要么是真网站但内容漂移、无法复现，要么是假网站但单一且局限于点击/文本。WebArena-Pro 把可重置的容器化后台状态、音视频工具（transcribe()、extract_frames()，全模态 Agent 则可 listen()/watch()）、跨多站操作和人工校验任务组合起来。各任务隔离、状态可恢复，支持并发复测。

验证与边界：论文的被测配置最佳任务成功率为 62.3%，这是作者的基准结果，不是所有 Browser Agent 的普适成功率，也不能直接外推到真实生产网站。任务覆盖更广但仍是受控应用；维护容器和判分逻辑存在成本。技术新颖性：中高（可复现多模态评测）；值得实测：高。建议用于独立验证 Agent 工具/Harness 的真正收益：冻结任务版本，分别比较 Chromium、WebKit/Firefox（若适配）、Kitesurf 上的完整成功率、独立最终状态、端侧音视频处理成本。来源：原论文（11/13）、原始仓库。

浏览器技术

Edge：同一 11 月 17 日 Ignite 公告还提到预览版 Extension leak control，可以阻止企业安装的扩展读取受保护网页；它是浏览器内的细粒度数据边界，而不只是扩展安装白名单。Remix 可通过自然语言改变网页的本地展示与部分操作体验，官方称 GA；这些是产品能力与安全策略的更新，并不代表已有独立新 Web API 标准。详情见 原文。

Chromium、WebKit/Safari、Firefox、Opera、Brave：本期独立检索未核实到足够重大的、可明确判定为 11/17—18 首发的底层标准或引擎机制。过去几期的 Spatial CSS、HTML-in-Canvas、WGSL Shader Print/FP8、Brave POPRF 不重复上头条。Kitesurf 补推属于 Browser Runtime 架构线，不应被误称为 Chromium 内核演进。

端侧 AI

过去 24 小时未核实到可与上期 Superfluid 相比的新端侧模型推理算法/Runtime 发布。本期不复制旧研究填栏。与端侧 AI 最相关的工程变量仍是：多任务争抢推理资源时的 TTFT p95、缓存正确性、低精度数值一致性及浏览器硬件能力差异。对 Edge 所宣称的 Token 节省，先取得任务集和独立对照后才可升级为技术结论。

浏览器 × AI

本期三个方向恰好回答 Browser Agent Runtime 的三个不同问题：谁有权执行（Edge 身份与策略）、由什么轻量引擎执行（Kitesurf Workers/WASM）、怎么判断真的执行成功（WebArena-Pro 可重置多模态任务与状态评分）。三者可以组合成为开放式的验证台，但这是工程建议，不是现成的一体化产品。

可落地的局部闭环：在同一个冻结任务上，Agent 自选工具运行 → 采集 DOM/Network/Console/Trace → 独立评估最终状态 → 生成候选 Harness/Runtime 改动 → 重放三引擎对照 → 保留或撤销。此处是建议的实验设计，不能算今日任何项目已证明完整实现。

今天的一个判断

Browser Agent 下一阶段的技术分界线，可能不是再增加浏览器操作工具，而是把执行环境做得更小、身份边界做得更明确、验收做得更独立。其中 Kitesurf 最值得安排一次架构级对照实验；Edge 的 Agent 身份值得作为受管理浏览器运行时的设计参考；WebArena-Pro 则适合作为验证“自动改进是否真的有效”的基础设施。三个项目的官方宣发、开源事实、论文结果和独立实测仍严格分开。
