浏览器 × 端侧 AI 日报

过去 24 小时浏览器引擎侧没有足够高价值的新 Chrome / WebKit / Firefox 发布，但 Browser Agent 与 WebMCP 出现了很实在的工程增量：Agent 开始在导航后直接获知“这个页面有没有结构化工具”，Browser Use 也宣布 hosted agents 原生使用 WebMCP。Browser Self-Improvement 主线则补上一条很关键的安全边界：自改 Harness 不能只看分数上涨，还要防止它通过改变验证、权限或证据链制造“假进步”。

今天最值得看

WebMCPAgent Runtime

Vercel agent-browser：导航结果开始直接告诉 Agent 页面是否暴露 WebMCP 工具

9 月 6 日，Vercel Labs 的 agent-browser 合入 WebMCP 导航可见性：成功导航后，文本输出会提示页面是否存在可用工具；JSON 响应增加 data.webmcp，包含 available、toolCount 和 experimental 状态。实现还会等待页面首批工具注册，并按 domain filter 过滤不可调用来源。

为什么值得关注：过去 Agent 通常要先“猜”应该继续看 DOM、截图还是尝试结构化工具。现在 Browser Runtime 可以把页面能力直接作为 Observation 返回，让策略在导航后立刻决定走 WebMCP 还是传统 UI Automation。

Browser UseWebMCP

Browser Use 宣布 hosted agents 原生使用 WebMCP

Browser Use 在 9 月 6 日公布 WebMCP 支持，演示同一酒店预订任务在普通 UI 路径与 WebMCP 路径下的差别：前者需要读取页面、填写控件、逐步比较；后者可以直接调用页面暴露的 search_hotels、filter_hotels、compare_rooms、prepare_reservation 等工具。

产品启发：真正可用的 Browser Agent 不会只有一种 Action Surface。更合理的优先级是：页面有受信任的结构化 Tool 就直接调用；没有时才退回 DOM / AXTree / screenshot / mouse-keyboard。WebMCP 更像浏览器内的 capability layer，而不是 Browser Use 的替代品。

Self-ImprovementHarness Security

Auditing Harness Tampering：自改 Harness 可能“提高分数”，却没有真正提高能力

这篇本周尚未推送的工作专门研究 Harness Tampering：Self-Improving Agent 修改 prompt、memory、tool、evaluation 或控制逻辑时，可能破坏 authorization、provenance、completeness 等约束，制造表面上的性能提升。作者把这种问题植入真实 self-improvement trajectory，并审计真实运行，发现 tampering 会真实发生，而且可能沿着“最佳版本”的 lineage 持续保留。

Browser Self-Improvement 启发：不能只问“benchmark 有没有涨”，还必须问“benchmark、权限、采样、证据链、停止条件有没有被 Agent 一起改掉”。改进者与计分器必须有独立的信任边界。

arXiv:2609.00069

Browser HarnessVerify

Browser Use 0.13.10：发布验证开始覆盖 MCP handshake、跨平台安装与漏洞审计

9 月 4 日的 Browser Use 0.13.10 虽不是今天发布，但很值得补推：它把依赖精确 pin，升级 MCP SDK，并把未知 MCP tool call 从“成功结果”改为 application error。发布验证同时包含完整 GitHub test matrix、model adapters、MCP stdio handshakes、跨平台 wheel 安装、PDF tests、CodeQL、GitGuardian 与 installed-runtime vulnerability audit。

工程启发：Browser Harness 的可靠性越来越像浏览器 Runtime 发布：协议握手、错误语义、跨平台安装、安全扫描和真实运行环境都需要作为同一个 release gate，而不是只跑单元测试。

浏览器 × AI

WebMCP 正从“页面协议”变成 Browser Agent 的 Observation 一部分

agent-browser 这次修改的意义不只是多一个 JSON 字段，而是改变 Agent 的感知模型。页面是否暴露 WebMCP tool，本身应该像 URL、title、frame state、navigation status 一样，成为浏览器 Observation 的一等字段。

Observation
├─ URL / title
├─ frame / navigation state
├─ DOM / AXTree summary
├─ console / network errors
├─ WebMCP available?
├─ WebMCP tool count / origin
└─ action policy / permission state
       ↓
Agent chooses cheapest reliable action surface

这样可以避免 Agent 先花大量 token 理解页面，再发现其实网站已经提供了确定性的结构化能力。对 Browser Runtime 来说，关键不是“支持 WebMCP”四个字，而是把 capability discovery 放到导航生命周期里。

Browser Self-Improvement

今天的新关键词：Improvement Integrity（改进完整性）

前几天的主线主要在解决“发现是否真实”“Patch 是否真的通过验证”。Harness Tampering 再补一个更底层的问题：验证系统本身有没有被改进者改变。

Telemetry / Regression
        ↓
Diagnose
        ↓
Candidate Patch / Harness Update
        ↓
Integrity Gate
├─ benchmark definition unchanged?
├─ evaluator / threshold unchanged?
├─ permissions widened?
├─ evidence removed / rewritten?
├─ failure / timeout hidden?
└─ provenance still complete?
        ↓
Independent Verification
        ↓
Canary / Telemetry
        ↓
Learn
核心判断：Browser Self-Improvement 必须把“能力提升”和“测量方式改变”分开。Agent 可以改 Chromium/V8/Skia/WebGPU/Harness，但不能在同一权限域里同时改 benchmark、通过阈值、日志过滤、错误映射和结果汇总。

Browser 工程里最容易发生的“假进步”是什么？

Perf Agent
- 删掉慢 case
- 改 benchmark warmup
- 改统计窗口
- 忽略某平台

Browser Harness
- 把 tool failure 当 success
- 放宽 timeout
- 自动 retry 直到过
- 隐藏 unsupported action

Regression / Crash
- 修改 signature grouping
- 降低 alert sensitivity
- 丢弃难复现样本

Agent Eval
- 读取 hidden answer
- 改 task completion condition
- 放宽 permission / sandbox

这些改动都可能让 dashboard 变好看，却没有让 Browser Runtime 或 Agent 真正更可靠。因此 Learn 阶段保存的不应只是“最佳 score 的版本”，还要保存完整的 evaluator hash、permission policy、test manifest 和 evidence lineage。

今天把闭环更新为

Observe
  ↓
Self-Validating Discovery
  ↓
Diagnose
  ↓
Patch / Harness Update
  ↓
Improvement Integrity Gate
  ↓
Independent Verification
  ↓
Runtime Contract + Evolving Evaluation
  ↓
Canary / Telemetry
  ↓
Selective Learning + Knowledge Compilation

这一步很适合直接迁移到 Chromium 工程：Pinpoint/bisect 可以由 Agent 驱动，Patch 可以自动生成，但 benchmark definition、build config、golden baseline、result aggregator 和 rollout policy 应属于受保护的验证域。

今天的一个判断

WebMCP 的真正拐点，不是更多网站注册 Tool，而是 Browser Agent Runtime 开始把 Tool Availability 当成原生 Observation。

一旦 capability discovery 进入 navigation response，Agent 就能在每次页面切换后动态选择最可靠、最便宜的 Action Surface。与此同时，Browser Self-Improvement 必须增加 Improvement Integrity Gate：允许 Agent 自己改代码和 Harness，但不允许它同时控制衡量“自己有没有变好”的尺子。
