今天最值得看

1. Jev Decision Hijacking：结构化决策降低 Prompt Injection 风险，但不能消除

研究用 510 个重建的 InjecAgent cases 测试 Jev typed probabilistic decision。恶意页面内容会移动 action probability；adaptive attack 在 score feedback 下把 fresh validation 成功率从 1.8% 提升到 3.5%。小 decision margin 和攻击者对 observation 的控制程度会增加风险。

为什么值得关注：Browser Agent 常用“页面 observation → action/target”的快速决策结构。Typed output 只能限制输出空间，不能阻止不可信页面影响允许动作之间的概率。

工程启发：Browser Runtime 应保留 observation provenance、decision margin、confidence 与 capability policy；低 margin 或高风险动作升级给 verifier/更强模型。

Decision Hijacking 论文

2. BrowserSkill：真实登录浏览器的交互权限从 CLI flag 上移到 Browser Runtime

BrowserSkill 最近把“借用用户 Tab 是否确认”“是否允许 Agent 请求人工帮助”变成浏览器 Profile 内持久化的 Automation settings；legacy unattended/no-confirm 参数不能覆盖浏览器侧设置，新协议要求 request-help 实际经过浏览器策略。

为什么值得关注：权限真相从 Agent/Harness 参数迁移到 Browser Runtime，低权限 Agent 不能靠命令行参数自行扩大权限。

工程启发：Harness 只能请求能力，浏览器保存的用户策略才是权威来源。Tab borrow、human handoff、credential/network 都可沿此模式实现。

Tencent BrowserSkill

3. EvoPathBench：Self-Improvement 不能只看最终分数

EvoPathBench 固定 base model/tools，在 artifact-level self-evolution 的多个 checkpoint 冻结 Memory/Skill，再用 held-out episodes 测 generalization、retention 和 rule adaptation。实验发现 distribution shift 会削弱部分收益，一些 evolution path 会遗忘旧能力，而且没有方法稳定完成 rule adaptation。

工程启发：每次 Learn 都应生成 capability checkpoint，对历史关键能力做 held-out replay；Promotion 不只比较 Candidate 是否优于 HEAD，还要检查是否保留旧能力。

EvoPathBench 论文

4. Agensh：大型工程 Agent 可从中央调度转向 Shared Workspace + Self-Assignment

Microsoft Research 的 Agensh 用 shared workspace、message interface、shared context 支撑无中央 orchestrator 的 cooperation loop。ProgramBench 中从 1 扩到 128 Agent，平均 test-pass rate 从 19.31% 到 28.78%；pandoc 扩到 1,024 Agent 时从 33.89% 到 55.06%。实验没有控制总 compute，也没有直接证明去中心化优于中央调度，因此应视为组织结构信号。

工程启发：Chromium Self-Improvement 可让 Trace、bisect、patch、build、WPT、perf、security workers 自行 claim 工作，共享 Experiment Workspace 与 Evidence，而不是让一个 Orchestrator 理解全部子系统。

浏览器技术

Browser Runtime 应成为权限事实来源。 BrowserSkill 的实现说明浏览器 Profile 可以保存用户授权，CLI/Agent 只能发起请求。AI Native Browser 可继续扩展到 Origin、Network endpoint、Credential、JS execution 与敏感表单提交。

端侧 AI

Fast Decision Model 必须显式处理 uncertainty。 Jev 类 typed decision 适合 element ranking、action selection、goal/stuck detection，但 schema-valid 不等于安全。端侧模型应暴露 margin/confidence：高 confidence、低风险动作本地执行，其余升级。

此前 Privilege-Preserving Learning 关注低信任内容不能通过 Memory 获得更高权限；今天的结果进一步说明，即使完全不写 Memory，不可信 observation 也能在当前 decision step 推动动作概率。因此 provenance 与 capability enforcement 必须位于模型之外。

闭环位置：Verify → Promote → Learn。EvoPathBench 已证明 endpoint score 会掩盖 distribution shift 与 retention loss。迁移到 Chromium 后，Skill/Rule/Memory 更新应像代码 patch 一样带 regression suite：新学会 compositor 修复模式后，还要重放 scheduler、scroll、GPU process、platform-specific 的历史代表案例。

每个 artifact 应记录 capability vector、scope、evidence、last verified milestone；如果新 artifact 让旧 checkpoint 下降，应阻止 promotion 或缩小 scope。

开源与论文 / 工程实践

Agensh 与昨天的 Evidence Retention / Context Bounded 可以组合：Shared Experiment Workspace 持久化 regression evidence、candidate lineage、build/benchmark result；各 worker 只加载当前任务所需的 bounded context，自行 claim Trace/Bisect/Patch/Build/WPT/Perf/Security 工作，最终统一经过 Independent Promotion Gate。

今天的一个判断

Browser Self-Improvement 的 Learn 阶段不能只问“新知识有没有用”，还必须问“它让哪些旧能力退化了”。

长期 Skill/Rule/Memory 应像带版本和回归测试的工程资产，而不是不断增长的提示词。每次知识更新都产生 capability checkpoint；只有 Target Gain、Generalization、Retention 与 Rule Adaptation 达到门槛，才进入长期 Learn。同时，结构化端侧 decision model 也不能自己保证安全，Observation provenance 与 Capability Policy 仍应由 Browser Runtime 强制执行。
