今天最值得看

1. Wap：把本地 Agent 与 Chromium Patch Series 放进一个浏览器项目（11 月 7 日新仓库）

发生了什么：minpeter/wap 于 2026-11-07 15:32（北京时间）创建，尝试构建 Chromium 下游浏览器 + 本地 Daemon + CLI + MV3 侧栏 + Native Host。仓库包含固定 Chromium Revision、顺序化 Patch Series、构建和原生 QA 脚本、详细的安全模型。其本地身份以安装该软件的操作系统用户为边界，Daemon/CDP Gate 用安装密钥的双向挑战认证，明确说明不同 accountId 不构成隔离的安全主体。

值得关注：与仅仅通过 CDP 连接现有浏览器不同，Wap 探索将 Agent 能力和安全契约嵌入浏览器发行版，适合作为研究原生 AI Browser 的工程材料。

重要限制：仓库自行标明“公开源码分发尚未通过审查”，项目范围尚未授予明确开源许可证，部分资产、Patch 来源、凭据和发布签名仍待处理；CI 也未证明完整 Chromium 编译与产品二进制验证。故公开可读不等于许可完整、可合法再分发的开源浏览器。建议研究架构与安全边界，不直接集成或分发。

2. browser-verified-skill：Agent 探索一次，编译出可重放 Playwright 脚本（11 月 7 日新仓库）

发生了什么：OMD-123/browser-verified-skill 于 2026-11-07 21:12（北京时间）创建，采用 TypeScript/Playwright，提供 CLI、MCP、操作策略门禁、审计工件、可编译的确定性脚本，以及针对失效定位器的局部修复。明确拒绝验证码绕过等隐蔽访问方式；登录/验证码交给人处理。其 package.json 列出单元、集成、E2E、覆盖率和验收脚本，并标注 MIT。

为什么重要：Agent 不必每次为同一网站重新进行昂贵的探索；把成功操作变成附带证据的脚本，再以常规 Playwright 执行，是从“会做任务”走向“可复用工程资产”的实用路线。

工程启发：可探索 Task → Evidence → Policy Check → Compile → Independent Replay → Skill Promotion，独立执行时不再让原 Agent 的判断充当通过证据。限制：目前是仅有少量外部关注的早期项目，作者“self-healing”等描述尚无公开跨站成功率或长期误修率的独立评测。

3. ghost-qa：让 Coding Agent 交付前真正跑一遍桌面/移动浏览器（11 月 8 日新仓库）

发生了什么：avivgerz-hue/ghost-qa 创建于 2026-11-08 03:23（北京时间），提供 npx ghost-qa test http://localhost:3000，基于 Playwright 自动遍历开发环境页面和部分交互，同时检查 Console/React Hydration、网络 4xx/5xx、移动端横向溢出、可访问性和性能资源问题。可生成 Markdown/JSON/HTML 报告；init 把浏览器验收规则写入 Agent 使用的配置文件；可通过 MCP 触发检测。

工程启发：用真实浏览器错误和移动视口差异阻止“代码编译成功就宣布完成”。尤其适合 Web 前端自动验证台的早期工具目录；关键指标应是误报率、误点率、真正复现的 Bug 比例，而非扫过多少 DOM 元素。

重要边界：“自修复”主要通过把报告交还给外部 Coding Agent 实现，不能说这个 CLI 自己完成代码修改。作者的自动点击会屏蔽常见支付/删除关键词，但未知网站操作仍可能有副作用；建议仅用在本地受控测试环境，不能凭 README 视为真正无风险。

4. LiteRT-LM：权重去重与运行时版本门禁同时落地（11 月 7 日合并）

发生了什么：Google 的 LiteRT-LM PR #4454 于 11 月 7 日 09:02（北京时间）合并：默认将符合条件的 TFLite 权重从模型 FlatBuffer 外置到 .litertlm 尾部的 TFLiteWeights 节，多个模型完全相同的权重可去重。PR #4455 于 09:27 合并，要求含外置权重的模型元数据至少标注运行时 0.19.0，避免旧 GPU Runtime 加载时崩溃；PR #4453 同日合并，避免多 LLM Session 切换时不必要的 KV Cache 深拷贝。

为什么重要：端侧 AI 除了 Kernel 性能，模型包体、相同权重的复用、Session 切换开销和文件格式兼容性同样影响真实体验。尤其是模型产物升级必须有 min runtime version 这样的防崩溃门禁。

工程启发：可为 iOS/Android/Browser 的统一端侧模型资产定义版本契约，并测“首次下载、磁盘占用、运行峰值内存、切换耗时和旧 Runtime 失败方式”。限制：这些为已合并代码变更，并未公开本期的包体/延迟量化收益；它们属于 LiteRT-LM 通用端侧运行时，不能直接推断 WebGPU/手机端收益。

5. Lightpanda：并发 Browser Context 的权限与网络隔离进入跨版本验证（11 月 8 日更新，仍为 Draft）

发生了什么：Lightpanda #4151 正在尝试让一个 CDP 连接内的多个 Browser Context 各自拥有 Session、存储、HTTP Client、权限、坐标和视口。作者更新了跨 Context 的路由、取消及销毁回归测试，声称三 Context 探针的 30 项基础控制与 Chrome 一致。其前置 #4149 将权限覆盖移到 Session；#4150 将页面和 Worker 请求归属 Session。

工程启发：一个 Browser Runtime 服务多个 Agent 时，真正难点不是多开 Tab，而是权限、网络路由、事件句柄、销毁后回调和调试会话不串线。适合作为多 Session 隔离测试案例。状态：#4149 Open、#4150 Draft、#4151 Draft，均未合并；测试数据来自提交者和其 Fork CI，不能当作主干已交付特性。

可落地实验：先为 Browser Harness 提供两个独立工具：RunAndCaptureEvidence（记录浏览器 Revision/Origin/执行轨迹/网络与 Console/失败截图），ReplayAndCompare（新 Session 重放，带权限与结果断言）。只有独立重放通过才保存或升级 Skill；长期失败则降级或撤销。这是“建设工具和可探索环境”而不是固定 Agent 工作流：由 Agent 自行决定何时调用，验证规则保持独立。

目前没有证据表明 Chromium/WebKit/Firefox 已实现 Telemetry → 自动诊断 → Patch → Canary → Learn 的完整自主闭环；现有案例主要落在 Observe、Diagnose、局部 Verify 和 Harness 资产回流。

今天的一个判断

下一代 Browser Agent 的护城河可能不是自动点击能力，而是从一次探索生成“有证据、可审查、能重放、过期可撤销”的长期资产。从今天新项目和真实 PR 看，工具目录、Session 权限边界、模型包兼容门禁和可回放测试，比复杂的固定 Agent 流程更值得率先建设。
