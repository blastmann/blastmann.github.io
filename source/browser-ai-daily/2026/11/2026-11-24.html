今天最值得看｜Ladybird 首次 Alpha 与 MoMoVL 模态感知量化

1. Ladybird 首次 Alpha：独立浏览器引擎终于进入可持续分发阶段

发生了什么：11 月 23 日（UTC），Ladybird 发布首个 Alpha，GitHub Release 标签为 2026.47.7，对应提交 4e9acf4。macOS 和 Linux 已有下载包，采用滚动更新；Windows 不属于这次正式分发范围。项目自主实现 HTML、CSS、DOM、布局、JavaScript 和 WASM，并非 Blink、WebKit 或 Gecko 的 fork。

技术新在哪里：这次发布不是单日创造新算法，而是使多年积累的独立架构可以直接下载实测。10 月 31 日工程月报记录了三项关键机制：样式和布局移至独立线程，绘制记录也独立于 JS 主线程；LibJS 引入基于运行时类型信息的 JIT；LibWasm 改用自有解释器和 JIT。尤其值得看的是主线程长任务期间，涉及 width/font-size 等布局的动画及 CSS :hover 仍可更新；JS 同步读取布局时必须等待相应工作，避免陈旧数据。与传统浏览器仅让部分合成动画脱离主线程不同，这是更深的渲染并行化实验。上述机制来自 10 月背景材料，不是本周才提出。

Alpha 的多进程设计还包括跨站 Renderer 隔离、按站点划分的网络进程，以及进程外图像解码。WebDriver 和 Firefox DevTools 协议为已有自动化与调试工具提供入口，但不应假定 CDP 兼容或全部 WebDriver 能力已经完善。

证据：官方 11/23 发布与带签名标签的 Release一致；10 月工程月报提供代码 PR、演示和自报基准。Phoronix实际进行了短时间试用，The Verge确认发布。独立报道不等于性能、兼容和安全全面验证，本期没有运行安装包。项目明确不作当前安全保证，不建议用 Alpha 登录敏感账号。

技术新颖性：高（独立引擎与渲染架构）；值得实测：非常高。在隔离测试环境用相同页面、同一硬件和版本记录，对比 Ladybird、Chromium、WebKit 和 Gecko：主线程长任务期间的布局动画、输入延迟、同步读取 layout 的等待时间、CPU/内存、WebDriver 兼容性，以及复杂 SPA 的功能正确性。单纯 WPT 通过数量不能代替这些指标。

2. MoMoVL：根据视觉和文本的不同敏感性，为 MoE 专家分配不同精度（11/18 论文，七日补推）

发生了什么：研究者 Dongkeun Lee 与 Wonjun Lee 于 11 月 18 日提交 MoMoVL，论文注明获 WSDM 2027 Findings 接收。其目标是在有限内存中部署混合专家视觉语言模型。不是只按整体专家访问频率分配 INT2/INT4，而是分别测量视觉和文本 token 的专家路由，再结合由损失梯度估计的量化敏感性形成重要性评分，离线生成每个专家的精度配置。推理时不必逐请求动态重新决定所有专家的精度。

相对现有方法：Fate、MoE-APEX 等依据路由频率或权重分配精度，MoMoVL 额外处理模态差异。实验以 MolmoE-1B（总参数 7.2B）和 DeepSeek-VL2-Tiny（3.4B）为对象，覆盖八项视觉语言基准。相对统一 INT4 的全 LLM 骨干量化基线，MoMoVL-Weight 的模型内存指标分别下降 15.44% 和 10.49%；多数测试有一定准确率损失，较小的 DeepSeek 模型在部分基准也落后于其他混合精度方法。只量化 LLM 骨干，不代表整机峰值内存同比下降。

证据与限制：论文、全文与实验表及MIT 研究代码可检查；代码提供校准脚本、精度配置和评测脚本，MolmoE 校准要求超过 40GB GPU 显存。校准与部署应分开看，尚未独立复现手机 NPU、WebGPU 或能耗结果，也未确认混合 INT2/INT4 kernel 在目标 Runtime 的效率。仓库创建日期未核实，不称为今日新仓库。

技术新颖性：中高；值得研究：高；移动端直接部署成熟度：低。建议在网页截图、OCR、表单理解与纯文本指令组成的保留集上，固定内存预算比较均匀量化、普通专家重要性量化和模态感知量化，测正确率、权重内存、运行峰值、TTFT、吞吐和功耗；优先使用已公布的配置复现，避免从手机上重新校准。

端侧 AI

MoMoVL 的启发是多模态任务的精度分配应考虑不同输入模态对模型质量的影响，而非只看全局访问频率。需要将压缩后权重的体积与真实 Runtime 的峰值内存、反量化成本及设备功耗分开评价。已知 Runtime 的常规 Release、Issue 检索没有提供本期另一项足够明确的新机制；例如 LiteRT-LM #4743 仍为开放的 Android 结构化输出崩溃报告，未验证修复。

浏览器 × AI

Ladybird 的 WebDriver 入口使相同的 Agent 任务有机会在独立引擎上执行，检测 Harness 是否暗中依赖 Chromium 特有行为；MoMoVL 则提供端侧视觉感知压缩的实验方向。两者并非已完成的集成产品。

Browser Self-Improvement

与 Alpha 发布相关的历史证据特别值得看：Ladybird 10 月月报披露团队以 WPT 为目标，让 AI coding agents 补齐功能。10 月 22—27 日通过子测试数约从 212 万增至 218 万，10 月全月增加 75,650 项，月底为 2,184,722 项。官方月报明确描述该过程，Simon Willison 11/23 的文章也重点讨论这项历史数据；后者不是独立重跑。不能将这些数量等同于 6 万个不同缺陷或生产兼容率。

闭环：Observe（WPT 失败）→ Diagnose（Agent 定位缺失功能，诊断细节未公开）→ Improve（Agent 参与修改实现）→ Verify（WPT 通过数量）→ Learn（没有公开持续经验沉淀、自主选择目标或长期 Canary 的证据）。Alpha 的自愿崩溃报告、网站问题报告和滚动更新可补充真实使用反馈，但未证实这些反馈自动回流 Agent。可迁移方法：使用固定版本 WPT 与独立保留集，记录每个改动新增通过与新增失败，并检查性能和安全约束；不要仅优化通过数。

今天的一个判断

独立浏览器引擎的出现，比新增一批 Chromium 包装项目更值得关注。建议优先用 Ladybird 测长 JS 任务期间布局动画与 hover 的响应，以及以 WebDriver 运行跨引擎保留任务。它既能检验渲染并行化的真实收益，也能为 Browser Agent 验证环境提供另一种独立实现。MoMoVL 则值得作为端侧视觉模型内存预算实验的候选。
