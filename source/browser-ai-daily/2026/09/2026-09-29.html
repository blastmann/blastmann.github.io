今天最值得看

1. WebKitGTK / WPE：Skia compositor 继续稳定化，验证边界跨到 ANGLE / Skia

Igalia 9 月 29 日周报显示，新 Skia compositor 继续修复 3D transform、damage region、paint order、filter surface 与 background artifact；同时修复退出阶段的跨线程 EGL 生命周期 crash：现在会等 GPU process 停止 WebGL thread、Web process 关闭页面后，再由主线程销毁 EGL display。

为什么值得关注：这类问题由 GPU process、WebGL thread、EGL 与 compositor 生命周期共同决定。WSA-2026-0006 还首次把 bundled ANGLE 与 Skia 的安全修复纳入 WebKitGTK/WPE advisory，说明验证边界不能只停在 WebKit 自身源码。

工程启发：Self-Improvement verifier 应建立 dependency-aware regression matrix：Browser Engine、GPU process、ANGLE、Skia、driver/backend 与平台生命周期属于同一验证面。

Planet WebKit：WebKit Igalia Periodical #79

2. Firefox 157 Nova：Sidebar / Vertical Tabs 进一步成为一等 Browser UI

Mozilla 9 月 29 日宣布 Firefox 157 已发布 Nova，这是自 2021 Proton 以来最大的一次 Firefox UI refresh。Toolbar 与 Sidebar 贴合窗口边缘，Sidebar 的角色更重，Vertical Tabs 成为 first-class layout；现有主题大多继续工作，但背景图、颜色落点和部分属性的可见效果发生变化。

为什么值得关注：对 AI Native Browser 来说，Sidebar 越来越接近浏览器框架的一部分。Agent、AI history、task state 和用户确认长期存在时，比网页 overlay 更适合作为稳定 UI surface。

工程启发：AI 功能应优先进入 Browser Chrome 层，同时把 theme/add-on compatibility 纳入 UI regression。

Mozilla：Nova is here

3. peerd：把 Agent Harness 直接建立在 Browser Primitives 上

过去一周值得补推的 peerd 是直接运行在浏览器内部的 Agent Harness：使用 Workers、Origins、Sandbox、OPFS、WASM/WASI、WebRTC、WebAuthn 与 WebExtensions，能够操作真实登录 Tab，同时启动 JS notebook、WASM Linux VM 等本地计算环境；推理可选择云模型、localhost 模型或实验性的 WebGPU local model。

为什么值得关注：它不是把 Browser 当成远程工具，而是把 Browser 本身当 Agent Runtime。Identity、Storage、Sandbox、Origin、Tab、Compute 与 UI 都可直接利用浏览器原生边界。

工程启发：重点观察 capability、signed-in session、sandbox 与 local compute 的组合，这条路线与 Local Small Model + Browser Harness + Cloud Model 很接近。

4. EVOHARNESSBENCH：Harness 自己升级也会让 Agent 遗忘旧能力

过去一周未推送的重要 benchmark EVOHARNESSBENCH 把 non-stationarity 放到 tools、skills、specialist agents 组成的 Harness 本身。它包含 17 个多阶段 harness streams、802 个任务、520 个 tools、42 个 skills 和 62 个 agents。实验发现，仅扩展 Harness 就可能让以前已解决的任务退化，而且 retention 与适应新能力并不总是同方向。

为什么值得关注：Browser Agent 会持续增加 DevTools、WebMCP、Memory、Skill、Verifier 和 local model routing。工具越多不保证系统越强，新增 capability 本身就是 regression source。

工程启发：每次 Browser Harness 增加 Tool / Skill / Agent，都应像浏览器代码变更一样跑旧 capability regression。

WebKitGTK/WPE 今天的信息主要集中在 graphics：3D projection、damage、paint ordering、filter pixel alignment 与 GPU lifecycle 都在继续修正。Compositor replacement 的 promotion gate 不能只看 MotionMark 或平均帧率，还应覆盖视觉 correctness、damage correctness、process teardown、WebGL/Canvas、ANGLE/Skia security 与多 backend。

端侧 AI

peerd 说明 Browser 内已经能组合 OPFS + WASM/WASI + Worker + WebGPU + WebExtension。端侧模型可承担高频 fast path，WASM sandbox 承担确定性计算和工具执行，复杂推理再升级云端。关键不再只是“模型能否在 WebGPU 跑”，而是模型如何进入受浏览器权限和生命周期约束的 Runtime。

浏览器 × AI

Firefox Nova 强化 Sidebar/Vertical Tabs，peerd 把 Harness 放进 Browser Primitives。组合来看，Agent 的持久任务状态、权限确认、运行日志和本地模型状态适合存在 Browser Chrome；网页只作为被观察和操作的内容环境。

开源与论文 / 工程实践

可以把 Browser Harness 的 Tool → Skill → Agent → Capability 关系显式建图。新增 Chrome DevTools tool、WebMCP capability 或 local model route 时，由 dependency graph 自动选出需要重放的历史任务，而不是每次全量运行，也避免只测新 capability。

今天的一个判断

Browser Self-Improvement 的 Verify 不应该只知道“改了什么文件”，还应该知道“这次改动可能影响哪些运行时依赖和旧能力”。

浏览器本身就是跨进程、跨线程、跨图形库、跨平台的系统；Agent Harness 也正在变成 Tool、Skill、Memory、Model 与 Verifier 的依赖系统。下一步值得把 dependency graph 接到 regression selection：先做影响范围预测，再选择最小但覆盖充分的 replay/benchmark 集合，最后由 Canary/Telemetry 检查预测之外的长尾。
