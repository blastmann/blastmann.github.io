今天最值得看

1. browser-memory：让 Browser Agent 在下一次访问同一网站时自动拿到过去经验（11/08 新仓库）

发生了什么：hivecode-app/browser-memory 创建于 11 月 8 日 19:20（北京时间），MIT。它不是另起一个自动化浏览器，而是给 Playwright MCP 增加一个 Gateway，透传原有工具，并从真实网络和操作回执中提取域名级经验：成功路径、错误修复、死胡同和站点 API。首次到达站点时，Gateway 将此前经验附到导航结果，无须 Agent 主动搜索记忆。网络提取保留 API 结构、去除常见参数值，不保存响应体。

为什么重要：针对“Agent 自称保存经验，实际上什么都没留下”的问题，作者把证据捕获放到了工具执行路径而非 Prompt 中。项目还允许把审核后的步骤变成可调用的过程工具，失败两次的修复建议不再主动给出。

数据边界：作者的冷/热记忆比较在两站点任务上只有 4 对实验，报告中位轮数 15.5→12.5、耗时 105→73.5s、成本 $0.91→$0.74；样本极小且区间重叠，不可据此宣称普适提升。更要审查自动采集的页面信息是否含个人数据和不可靠的网页指令。工程启发：把 Tool Trace → Candidate Lesson → Independent Replay → Publish/Expire 做成独立基建，尤其需要区分“看到了响应”与“真正完成目标”。

2. Browser Harness：用 45 个真实站点对照定位“网络空闲”假超时（11/08 Draft PR）

发生了什么：browser-use/browser-harness #982 于 11 月 8 日提交，仍为 Draft、尚未合并。wait_for_network_idle() 错把在独立 CDP Target 结束的 Worker Script 和跨进程 iframe 文档请求当成永不结束的主页面请求，导致等待常常拖到 10 秒上限。候选补丁通过 Target attach/detach 识别请求归属，并保留真实页面尚未结束的请求。

验证证据：作者同时提供本地 Chrome 集成回归、266 个单测，以及两个云端浏览器对 45 个真实站点的同期重放。超时比例由 38/45（84%） 降到 3/45（7%），平均等待从 8.86s 降到 3.25s，没有出现原本正常却变为超时的样本。数字是 PR 作者测试，不是上游发布或第三方复核。

工程启发：Browser Agent 的超时/网络空闲判定必须知道 Page、OOPIF 和 Worker 的会话边界，且在改判定标准时用多站点正反例验证，防止单纯“更快返回”掩盖仍在加载的请求。

3. guadian-ondevice：Android 本地 1.7B 模型验证网页风险，同时公开失败实验（7 日补推）

发生了什么：guadian-ondevice 创建于 11 月 7 日 22:54（北京时间）。其 Android 实现从 URL、隐藏 WebView 的页面内容等收集证据，使用经 LoRA 微调的 Qwen3-1.7B/Q8_0（1.83GB）通过 llama.cpp 回答六项事实性问题，再由独立的 verdict_table.json 给出风险级别。项目强调页面内容不离开设备，但属于作者实现主张，尚需独立安全审查。

验证证据：技术报告 记录了六轮训练和两轮主动不采纳：部分版本降低漏报，却显著提高误报。最新版本在 156 条人工复核样本准确率 78.8%；188 个风险页面漏判 24 个（12.8%）。414 条测试中只有 156 条经过人工复核，其余采用模型复核，不能写成“414 条独立人工验证”。

工程启发：将模型输出限定为可审查事实、把策略放在独立规则表，并以漏判/误报/量化一致性多维度门禁决定是否晋级。该项目不是生产级防钓鱼产品，也不是 WebGPU 推理案例。

4. ccfox：Firefox/Zen 真实浏览器与 Claude Code 共享标签和可录制 Skill（11/09 新仓库）

发生了什么：thedankest/ccfox 创建于 11 月 9 日 06:43（北京时间），MIT。在 Zen/Firefox 侧栏调用本机已安装的 Claude Code，借助 Native Messaging/本地 Unix Socket 操作现有 Profile 的标签页，读取页面、Console 和 Network；可录制人工操作并导出 ~/.claude/skills/<name>/SKILL.md。记录过程声明剔除密码/验证码和常见 URL Token。

关键边界：macOS 是作者测试平台；普通 Firefox Release 不能持久安装源码构建的未签名扩展，需要 Developer/Nightly/ESR 或临时调试模式。侧栏聊天由自身批准卡约束；外部 Claude Code 的 MCP 调用依赖 Claude Code 自身的工具权限，不应误称两者具有同一审批策略。工程启发：研究多会话共享真实 Tab、人工接管、录制 Skill 与权限回执如何区分。当前为早期源码，未经独立安全审计。

5. gen-ai-rs：Rust/WASM 浏览器 Agent 主循环，把工具权限留在同源服务器（11/09 新仓库）

发生了什么：mraad/gen-ai-rs 于 11 月 9 日 00:03（北京时间）新建，Apache-2.0。它用 Rust/WASM 在网页内执行模型请求、工具调度、消息压缩和按需加载 Skill；MCP 工具在页面的同源服务器执行。原型主动移除了复杂编排、动态 Hook 和多 Agent 路由，提供模型调用与工具调用事件、超时及取消语义。

重要边界：“Agent 在浏览器内”不等于模型本地运行：默认模型可以通过 OpenAI 兼容 HTTP API 调用外部服务，宿主可另外接入浏览器本地推理引擎；实际操作权限和危险操作确认必须由服务端保证。工程启发：适合作为 AI Native Browser 的薄 Agent Runtime 研究材料：将模型决策、工具执行边界与可观测事件分离，而不是先设计固定工作流。

浏览器技术

社区信号：KetchUp3D 于 11 月 9 日进入 Hacker News 热门讨论。它并非本日创建：仓库早在 10 月 23 日成立。项目将一个 Rust 3D 编辑器同时构建为桌面程序和 WASM 网页，渲染优先使用 WebGPU，不满足条件时回退 WebGL2；支持本地保存与 SketchUp 几何导入，手机端不是当前目标。对 WebGPU Runtime 的启发是单套计算/渲染核心的跨平台构建、能力回退和真实复杂交互验证；产品性能暂无独立基准数据。

运行时问题：Lightpanda #4515 在 11 月 9 日 06:44（北京时间）已合并：当 iframe 资源加载被禁用时，仍给页面提供期望的 contentWindow/contentDocument，却阻止由 iframe 发起的 HTTP/WebSocket 请求。背景是此前的兼容修订导致真实网站多加载脚本与额外内存消耗。是“兼容性要求与资源预算冲突”的工程案例，并非 AI 自动修复闭环。V8 预编译库校验 #4523 仍为 Open：拟对下载文件和缓存校验 SHA-256，以避免损坏或替换的二进制进入构建；哈希校验不等于发行者签名。

端侧 AI

手机端证据：guadian-ondevice 把本地模型的“事实问答”与风险策略解耦，且用量化前后的一致性、漏判和误判选择模型，而不是仅看总体准确率。对于端侧模型实际发布，应增加模型版本、峰值内存、耗电、后台恢复、WebView 页面内容获取失败等观察项。

浏览器端：gen-ai-rs 证明的是 WASM Agent 控制层与工具边界，并非新的浏览器端本地模型速度突破；模型可云端、可本地的描述必须明确分开。KetchUp 则提供 Rust/WASM + GPU 回退的非 AI 工程验证参考。

浏览器 × AI

browser-memory 将站点经验注入工具返回路径；ccfox 让用户/Agent 共享真实浏览器；gen-ai-rs 把 Agent 主循环放在网页中但把实际工具保持在服务端。这三种方案的共同问题是：必须能够回答谁观察了页面、谁批准执行、哪个工具做了什么，以及所得经验能否被另一个会话复现。尤其不能把从网页抓到的 API 和文字直接提升为高权限指令。

可落地实验：给 Browser Runtime 的每条工具调用记录 {runId, browserRevision, targetId, frameId, origin, action, observedResult, permissionDecision, evidenceRef}。当模型提出等待策略、Skill 或性能优化时，在隔离 Session 用相同任务的基线和候选方案进行对照；明确把“没有超时”与“真正达到预期状态”分开判定。由 Agent 决定是否调用，不强制固定工作流。

当前边界：这些案例仅提供部分 Observe→Diagnose→Improve→Verify→Learn 环节。没有证据证明 Chromium/WebKit/Firefox 已存在从真实 Telemetry 到自动 Canary 和持续学习的完整自改进闭环。

今天的一个判断

Browser Self-Improvement 的关键不是让 Agent 记得更多，而是让旧经验能被独立复测、错误经验能够失效，且每一次“变快”不会损害结果正确性。今天的站点记忆 Gateway 和多 Target 网络空闲修订，分别提供了“持续积累”和“避免假成功”的具体例子。优先构建可信工具回执与对照验证，比建立更多固定编排步骤更有价值。
