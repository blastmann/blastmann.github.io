浏览器 × 端侧 AI 日报｜2026-10-05

今天最值得看

1. OpenAI Computer Use 的 10× 提速：Harness + 独立 Guardian

10 月 4 日公开的访谈转述中，OpenAI Codex 负责人 Thibault Sottiaux 将过去一年 computer-use 的约 10× 提速归因于模型与 Harness 共同优化：减少每次 action 前不必要的 reasoning、消除 Harness 小停顿并提高并行度；同时由第二个 AutoReview（内部称 Guardian）Agent 观察主 Agent。10× 目前应视为团队口径，而不是可独立复现 benchmark。

为什么值得关注：Browser Agent 延迟不只是模型 tokens/s；Action 前思考、工具往返、并行 observation 和 verifier 共同决定端到端体验。

工程启发：分别记录 Reasoning Latency、Observation Latency、Tool RTT、Idle/Stall、Verifier Latency；Guardian 与主 Agent 解耦后，可独立换成更快的小模型或规则系统。

访谈内容转述

2. DeepSeek Harness v0.2.1-alpha.1：Agent 开始直接生成自己的 Plugin Runtime

官方预发布版加入实验性 Claude Code Mods 兼容层，并明确当前目标是验证 Mods API 能力大致属于 DSH plugin 能力的子集；Plugin Manager 新增“让 Agent 创建插件”，Creator mode 可按需求直接生成插件；Developer Tools bundle 提供 raw session logs、对话双向定位和 Host diagnostics。

为什么值得关注：这已经接近 Recursive Harness Improvement：Agent 不只是使用 Tool，而是可以生成和调试自己的能力模块。

工程启发：迁移到 Browser Self-Improvement 时应采用 Plugin Candidate → sandbox → replay → capability/security regression → signed promotion，Plugin 本身也成为 versioned experiment artifact。

DeepSeek Harness 官方 Release

3. Firefox 小模型实践：先用网页结构做确定性 Routing，再调用专用 Prompt

Mozilla 最近公开 Shake to Summarize 的 recipe 优化：通用摘要 prompt 经常漏掉关键配料和步骤。团队没有增加模型分类 pass，而是优先读取网页 structured data，确定性识别 recipe，再路由到专用 prompt；在 curated recipe sites 测试中，完整且准确的摘要概率提高到原来的两倍以上。

为什么值得关注：Browser Runtime 已知的结构化事实，不应该再让小模型猜一次。

工程启发：DOM、Schema.org、MIME、Navigation type、权限状态、Tab/Frame identity 先成为 deterministic feature；只有语义不确定部分进入模型。

Mozilla 官方工程文章

4. Vivaldi 8.2 在 10 月 4 日继续回合 Chromium 154 安全修复

Vivaldi 10 月 4 日发布 Desktop 8.2 第八次小更新，将 Chromium 152 ESR 基线更新到 152.0.7977.155，并说明包含 Chromium 154 的安全修复。

为什么值得关注：浏览器安全修复并不总以升级同一 major 传播；下游可能通过 ESR/backport 消化上游变化。

工程启发：验证资产应绑定 security fix / patch lineage，而不只绑定 milestone；自动选 regression 时要知道安全修复是否已 backport 到当前 branch。

Vivaldi 官方更新

端侧 AI

Deterministic Router Before Model

Firefox 的 recipe 案例说明，小模型不需要承担 Browser Runtime 已经能确定的分类工作。更合理的端侧 pipeline 是：结构化特征 → deterministic router → task-specific prompt/model → output oracle。

业界做到哪：DeepSeek Harness 已允许 Agent 进入 Creator mode 生成插件；OpenAI computer-use 的访谈则显示独立 Guardian/AutoReview 已参与主 Agent 执行链。两者组合后，更合理的方向不是让 Agent 随意改自己，而是把 Harness change 当作与 Browser patch 同等级的候选产物。

迁移到 Chromium：如果 Agent 自动修改 Trace parser、bisect policy、benchmark selector 或 verifier prompt，这些改动同样必须有 candidate SHA、独立 replay、held-out regression 和 rollback，否则 Self-Improvement 很容易通过修改验证逻辑制造假提升。

开源与论文 / 工程实践

今天没有发现比过去几期已覆盖的 RRSI、ModularRSI、STITCH 更值得新增的 Self-Improvement 论文，因此不重复报道。更值得跟踪的是这些思想正在产品 Harness 中落地：Plugin 变成可生成对象、Verifier 变成独立执行角色、Browser Runtime 的确定性事实承担更多 routing。

今天的一个判断

Browser Self-Improvement 不能只管理 Browser Code 的变更；Prompt、Skill、Plugin、Router、Verifier 和 Harness 本身都应该进入同一套版本化 Promotion Pipeline。

一旦 Harness 可以由 Agent 自己生成或修改，真正需要保护的就不只是源码仓库，而是“决定如何观察、如何判断成功、如何晋升”的整个控制面。Browser Patch 与 Harness Patch 应共享同一套 evidence、replay、regression 和 rollback 语义。
