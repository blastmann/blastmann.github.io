1. WebKit Spatial CSS：让真正的 3D 场景服从 CSS 的声明式布局（11/16 官方技术预览）

发生了什么：WebKit 在 11 月 16 日介绍 Spatial CSS 开发者预览。visionOS 27.3 中 Safari 的实验能力围绕 <model> 提供 spatial: portal，将多个 3D 模型放进同一空间；沿用 CSS transform 和 position-anchor 进行 3D 变换和锚点对齐；以 @environment-map 复用环境光照、portal-action:orbit 配置旋转交互，调用 requestVolumetricScene() 将网页场景转为与页面保持联系的空间场景。

技术究竟新在哪里：过去为 3D 交互写 WebGL/WebGPU 应用往往自己管理场景节点、灯光和更新状态；这次尝试让布局、锚点、动画、媒体查询和交互跟随 Web 平台既有的声明式 CSS 机制。区别于此前报道的 HTML-in-Canvas：这里重点不是将普通 DOM 绘入 GPU 纹理，而是让 3D 模型的组合和布局进入浏览器样式系统。规范草案见 CSS Spatial Layout Module Level 1。

证据、状态及局限：WebKit 官方实现演示与标准草案；目前是 visionOS 27.3 Safari 中需通过 CSS Portals feature flag 开启的开发者预览，不是 Chrome/Firefox/Safari 全平台稳定 API。文中只证明官方演示及语法设计，未见跨引擎 WPT、无障碍、移动 GPU 耗电验证。技术新颖性：高；值得研究/实测：高。建议用 visionOS Simulator 对比 HTML/CSS Portal 与 three.js/WebGPU 自建布局的交互、动画、锚点跟随以及性能。来源：WebKit 原文（2026-11-16）、CSSWG 草案。

2. Superfluid：单台与多台本地设备统一调度，优先满足交互请求（11/13 论文，7 日补推）

发生了什么：Superfluid: Local AI Server for Distributed LLM Inference 于 11 月 13 日首次提交，研究如何让同一台设备上并行运行的多个 Agent 与用户交互共享推理，以及让跨 Apple、NVIDIA、AMD 设备的本地模型以一个 API 提供服务。basecompute/superfluid 是真实可访问的 Apache-2.0 代码仓库，支持 llama.cpp、MLX 和 BaseRT 等后端。

技术究竟新在哪里：不是再加一层兼容 OpenAI API 的代理，而是在推理执行层同时组合交互请求优先调度、共享 Prompt 前缀只计算一次、Token 在发给客户端前持久记账，以及跨异构机器按速度调度与失败接管。关键问题从“跑得动模型”变成“多个 Agent 竞争模型时如何维持首 Token 延迟和任务可靠性”。

验证与边界：作者在 Apple M5 Pro、Qwen3.8-27B 与八个并行 Agent 的测试中报告，交互请求首 Token 约 1.5s，比较对象的等待时间为 291—612s；跨六台不同芯片设备、64 个模拟用户、1 小时共完成 5,041 次请求；12 台 Mac Studio M3 Ultra 集群报告 10,656 tok/s。这些是论文作者的指定负载实验，不是独立验证，也不能概括为模型计算本身数百倍加速。多设备方案通常以设备保有相同模型副本进行请求调度，不等同于把一个模型的权重拆开在所有设备上联合运算。新颖性：中高（系统级组合）；值得实测：高。适合对比单 Mac 上多人/多 Agent 并发场景的 TTFT p50/p95、抢占公平性、取消与故障恢复。来源：原论文（2026-11-13）、原始仓库。

3. ModHarness-RL：把 Agent 的上下文压缩和纠偏逻辑当作可学习程序（11/13 论文，7 日补推）

发生了什么：论文 ModHarness-RL: Recasting Harnesses as Learnable and Evolving Programs for Agentic RL 于 11 月 13 日提交。作者把 Agent 运行时历史组织成结构化的 State 和有类型的块，用两个可执行程序操作这些记录：Compression 决定哪些历史信息进入上下文，Steering 仅在行为偏离或失败条件成立时注入指导。候选逻辑来自执行轨迹，在沙箱里运行检查、重放旧轨迹，再通过保留任务评测门禁；模型训练过程中可以更新 Harness。

技术究竟新在哪里：相对固定的 Prompt 模板、每日 Reflector 文字总结，改变的是运行环境中的可执行控制逻辑，并随模型行为变化更新，而不是每次在线调用另一个 LLM 总结历史。论文以 CodeSearch 为主，并分析 ALFWorld、BIRD SQL，涵盖 1.5B—8B 模型。作者报告多数设置比固定 Harness 获得更好的未见任务表现，但非独立复现。

边界与工程价值：这是 Agent RL 训练中的 Harness 共演化研究，不是已证明 Chromium/WebKit/Firefox 能自动修改浏览器内核。候选变更的安全与收益取决于旧轨迹回放范围和保留评测集；真实环境漂移、工具副作用与长期失效仍需解决。新颖性：高；值得深挖：高。可先脱离模型训练，构造 Browser Runtime 上的 typed traces、可回放的 Compression/Steering 候选和冻结评测集，再测 Token 消耗、失败率、回归与撤销。来源：原论文与提交记录。

端侧 AI

本期关注从单模型算力转向多任务推理调度。Superfluid 的交互抢占与共享前缀计算回答的是“多个本地 Agent 共用模型，用户聊天仍能及时响应吗”。论文中的队列等待显著缩短不应被等同为 GPU Kernel 加速；建议同样观察显存占用、模型副本开销、TTFT 尾延迟和公平性。原始资料：论文、仓库。

浏览器 × AI

Spatial CSS 的意义不是已经实现 AI Native Browser，而是将来 AI 生成的空间 UI 可以复用 CSS 的布局与响应式机制，减少专有三维 UI 代码。Superfluid 则使端内 Browser Agent、用户会话及后台任务共享本地推理服务成为更可评测的系统架构。二者都未在本期进行独立部署验证，不应把潜在用途写成已落地产品。

今天的一个判断

今天最值得研究的是“浏览器原生能力做声明式化，端侧 AI Runtime 做调度化，Agent Harness 做可执行且可验证的演化”。 三者分别减少 UI、推理和 Agent 控制层的应用私有逻辑。工程建议的优先级：先用 visionOS Simulator 验证 Spatial CSS 的语义/交互边界；再用真实多 Agent 并发复测 Superfluid 的 TTFT；最后把 ModHarness-RL 的 typed trace + replay gate 抽象为独立可组合的 ERSI 工具，而不是直接复制论文训练流程。
