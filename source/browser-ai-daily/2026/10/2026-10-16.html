1. Browser Use：真实 Chromium 修复导航中间态与高 DPI 截图偏移

发生了什么：10 月 16 日 07:50（北京时间）合入 PR #6089。云浏览器导航时短暂空 URL 触发 Agent 工具状态校验失败；高 DPI 下截图尺寸与 CSS 视口不一致，导致坐标点击偏移。修复用 about:blank 表达尚未提交的导航状态，并用 Page.getLayoutMetrics 将截图对齐到 CSS 视口。新增真实 Chromium 回归测试，作者报告 11 项驱动测试通过。为什么关注：模型意图正确，也可能被 Harness 的坐标转换与状态回执破坏。工程启发：记录设备缩放、视口、Frame ID、导航中间态、实际点击位置，跨 1/2/3 倍显示比例验证。

2. Chrome 155：10 项安全修复，明确记录 Claude 辅助发现 DOM 漏洞

发生了什么：10 月 15 日 Chrome Stable 更新至 Windows/macOS 155.0.8059.84/.85、Linux 155.0.8059.84，修复 10 项安全问题。Critical CVE-2026-110922 涉及 Prerender 释放后使用；High CVE-2026-110913 是 DOM 内存损坏，官方注明由 Anthropic 研究人员 Xinyang Ge 在 Claude 辅助下报告；其他问题涉及 V8、SVG、Compositing 与 Workers。为什么关注：AI 辅助安全发现进入真实浏览器发布记录。工程启发：保存最小复现、Sanitizer 输出、Browser Revision、修复版本和长期回归测试。不能据此声称 AI 自主完成 Patch、Canary 与学习。

Chrome 官方安全公告

3. agent-browser：域名限制拦截跳转后，导航不能误报成功

发生了什么：10 月 15 日合入 PR #2114。跳转到不允许的域名会收到 403 页面，但 open 命令此前仍报告成功。修复按 Frame ID 记录被拦截文档，主 Frame 最终落到阻止页时返回失败。为什么关注：网络拦截、导航完成与任务成功是不同状态。工程启发：操作回执必须携带最终主 Frame URL、策略结果和页面状态，不能用单一 success 掩盖拒绝。

原始 PR · 合并提交

4. Chrome DevTools MCP：独立 Profile 并行 E2E，38 秒降至 8 秒

发生了什么：10 月 15 日合入 PR #3175。每个 E2E 测试启动独立 MCP Server 与浏览器 Profile，因此可以并行执行。作者报告 index.test.js 在 96 核主机由 38 秒缩短至 8 秒；PR #3177 还并行执行互不共享状态的输入用例。为什么关注：验证预算与 CI 延迟限制了 Agent 提出的改动数量。工程启发：明确隔离可并行测试和共享状态测试，减少等待成本；单机结果不能外推到全量 Chromium CI。

浏览器 × AI

Browser Self-Improvement

Truthful Action Receipt：先验证操作回执，再让 Agent 学习

业界走到哪：Browser Use 已实现真实问题 → 复现 → Patch → Chromium 回归；agent-browser 完成错误回执 → Frame 级诊断 → Patch；DevTools MCP 完成隔离测试 → 并行验证；Chrome 安全公告显示 AI 辅助发现进入正式发布。公开资料尚不能证明完整的 Agent 自主 Canary 和持续学习。

迁移 Chromium：先做三组回归：（1）导航中间态与跨域重定向；（2）deviceScaleFactor 1/2/3 下截图与点击一致性；（3）独立 Profile 并行 E2E 与共享 Profile 隔离验证。每次保存 Browser Revision、Frame ID、Policy Decision、截图尺寸、CSS 视口、实际坐标与 Trace。Patch Agent 不得修改独立 Oracle 来掩盖失败。

今天的一个判断

Browser Self-Improvement 的下一块基础设施是可信的操作回执：区分 Agent 想做什么、浏览器实际做了什么，以及安全策略是否允许。只有三者一致，自动修复和学习才有可靠依据。
