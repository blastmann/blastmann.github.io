浏览器 × 端侧 AI 日报

今天最值得关注的不是又一个“AI 浏览器”产品，而是 Browser Agent 的两条基础设施线同时变清晰：一条是本地真实浏览器正在形成标准化的 Agent Bridge；另一条是 Self-Improvement 开始把 Harness 的经验演化与安全边界一起工程化。

2026-08-29 · 过去 24 小时优先 + 一周内未推送高价值补充

今天最值得看

Local Browser AgentNative Messaging

Agtweb：本地 Agent 直接操作用户现有 Chrome / Firefox Session

Agtweb 8 月 28 日更新到 0.6.2。它把浏览器扩展、Native Messaging、本地 bridge 和 WebSocket 组合成一条本地控制链：Agent 可以读取结构化页面内容、管理 Tab、点击/输入/上传文件，并直接使用用户已经登录的浏览器 Session。

启发：“Real Browser + Local Bridge + Agent”正在从零散原型变成明确产品形态。浏览器侧真正缺的不是更多点击 API，而是 Capability、身份、审计和用户确认的统一层。

Chrome Web Store

WebGPUAgent-ready Infra

Vercel Labs vgpu：WebGPU 开始被包装成“Agent 可理解、可验证”的工程表面

vgpu 提供 typed WGSL imports、浏览器 / Node(Dawn) / deterministic mock 三套运行环境，并给 Agent 提供离线文档、CLI、MCP 和 Skill。更有意思的是，它专门写了 agent-browser + WebGPU 的验证流程，在 Linux/容器中用 SwiftShader 做真实截图校验。

启发：对 Browser AI 而言，WebGPU 的关键不只是推理加速，而是能否进入 Agent 的“写代码 → 运行 → 截图/像素验证 → 回归”闭环。

GitHub: vercel-labs/vgpu · Agent Browser WebGPU 指南

Harness SecurityPrompt Injection

When Context Gets Root：Harness 可能把低权限网页内容“提权”为高权限指令

这篇 8 月 27 日提交、8 月 28 日更新的论文提出 instruction privilege escalation：Harness 在重新组织上下文时，可能把原本低权限、来自网页或工具的数据放进更高权限的 instruction channel。作者在 6 个 coding-agent harness 上测试 13 类攻击目标，说明问题并非只属于某个模型。

警告：Browser Agent 的安全边界不能只依赖模型 instruction hierarchy。Harness 在做 DOM 摘要、Memory 写入、Skill 提炼、跨 Agent 转发时，都必须保留 provenance 与 privilege label。

arXiv: 2608.27299

Self-ImprovementRCA

OpsHarness：成功/失败轨迹 → 原子改进提案 → 双门验证 → 可复用 RCA 专长

OpsHarness 不重造一个专用 RCA Agent，而是在通用 Agent 外增加可自进化 Harness。它对比成功和失败诊断轨迹，把证据转成 atomic proposals，再通过 dual-gate verification 才允许进入知识和工具库。论文报告在两个公开 benchmark 与工业部署中达到 59.0% top-1，较 bare general agent 提升 63.4%。

启发：这几乎可以原样映射到 Chromium 性能回归：Trace / Pinpoint / culprit CL → 诊断轨迹 → idea card → benchmark gate → Trusted Skill。

arXiv: 2608.25661

浏览器技术

本地 Browser Agent 的实现模式正在收敛

Agtweb 选择 Extension + Native Messaging + localhost WebSocket；同日更新的 Web Draw 则通过 Extension + 本地 MCP Server，让 AI 用压缩后的文本页面视图操作当前可见 Tab。两者都强调“使用用户正在看的、已经登录的浏览器”，而不是另开云端 headless browser。

值得关注的共同点：页面观察开始倾向结构化文本 / element handle，执行留在本地真实浏览器；这和我们之前的 Ghost Browser / 本地 Bardeen 路线高度一致。

Web Draw by Olib AI

但 Permission Model 仍然明显落后于 Agent 能力

Agtweb 的扩展权限是安装时一次性授予，并明确没有 per-site approval prompt。对普通自动化插件这可以接受，但一旦 Agent 能操作登录态页面、下载、上传和表单，这种模型会显得过粗。

Browser Runtime 应该补的层：Tab / Origin / Operation / Data Class 四个维度的 capability grant，并能做一次性授权、短期授权、持续授权与审计。

端侧 AI

WebGPU 的 Agent 可验证性比“又快了多少”更值得看

vgpu 把同一套代码放到 Browser、Dawn-backed Node 和 deterministic mock 中，使 Agent 能在没有真实 GPU 的 CI 环境里执行和验证 GPU 工作负载。它甚至明确指出 headless Chrome 在某些 WebGPU screenshot 路径上会黑屏，并给出 SwiftShader 的验证方案。

工程启发：端侧 AI Runtime 也应该有对应的 software backend / deterministic test backend，让模型路由、算子和 memory policy 可以离线回归。

Agent-ready Library 是新的基础设施设计要求

vgpu 把 docs、CLI、MCP、Skill 和可运行 examples 当成发布物的一部分。这意味着一个浏览器底层库如果希望被 Coding Agent 高频修改，文档和验证入口本身也要机器可发现、可执行。

今天的新变化：过去我们更多讨论“Agent 怎么控制浏览器”；今天更清楚的是，真正需要产品化的是中间的 Local Browser Bridge。它既要提供稳定 observation/action，也要承担权限标签、来源追踪、审计和验证。

Browser Self-Improvement

OpsHarness 给出了很像浏览器工程的 Self-Improvement 模板

它的关键不是“让 Agent 自己改自己”，而是把每次 RCA 轨迹变成候选经验，再经过验证进入可复用知识层。对于浏览器工程，可以直接替换对象：

Regression / Crash / Perf Alert
        ↓
Trace + Logs + Culprit CL
        ↓
General Engineering Agent
        ↓
Successful / Failed Diagnosis Trajectories
        ↓
Atomic Idea Card
        ↓
Benchmark Gate + Regression Gate
        ↓
Trusted Browser Engineering Skill

双门验证值得升级成我们的 Trusted Learning 默认结构

昨天我们提出 Trust Gate，OpsHarness 今天给了一个更具体的实现方向：新经验不能因为“这次成功”就写入 Memory；至少要同时通过当前问题验证和历史回归验证，防止局部过拟合。

建议：浏览器 Skill Store 可以把 admission gate 拆成 Case Gate + Regression Gate，后续再加 Security/Privilege Gate。

“When Context Gets Root”补上了 Harness 自身的权限污染风险

Self-Improvement 系统会不断把网页、Issue、Trace、Review、Agent 总结写入下一轮上下文。只要 Harness 在重写时丢掉来源层级，低权限数据就可能在下一轮变成高权限经验。

因此 Trusted Learning 还不够：Trusted Knowledge Store 中每条知识必须保存 provenance + privilege，并禁止在“摘要 / 提炼 / Skill 生成”过程中自动升权。

今天的一个判断

Browser Self-Improvement 下一步不应该继续只扩展“Learn”能力，而应该明确增加一个贯穿全链路的概念：Privilege-Preserving Learning（权限保持式学习）。

也就是说，网页里看到的一句话，即使后来被总结进 Trace 分析、Memory、Skill 或 Rule，也不能因为被 Agent 重写过就获得更高权限。经验可以被压缩、组合和继承，但它的来源等级不能被洗掉。

Observe(data + provenance + privilege)
        ↓
Diagnose
        ↓
Candidate Skill / Rule
        ↓
Case Gate + Regression Gate + Security Gate
        ↓
Trusted Knowledge
        ↓
Re-use with original privilege ceiling

如果把昨天的 Trusted Learning 和今天的发现合并，我更倾向于把 Browser Engineering Agent 的长期知识层定义为：Evidence-backed、Executable、Reviewable、Privilege-preserving。这比单纯“有 Memory 的 Agent”更接近可长期运行的工程系统。
