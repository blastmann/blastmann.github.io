WebMCPAgent Product Design

Chrome：WebMCP 工具设计从“暴露 API”转向“围绕用户目标构建工作流”

Chrome 新指南要求开发者先定义用户目标、初始状态和边界，再通过 role-play 拆解工具；工具错误要可恢复，最终还要用 Evals 和真实 Telemetry 持续更新工具定义。

启发：Agent Tool 不再只是 RPC schema，而要显式定义状态、权限、恢复路径和成功判定。

Chrome WebMCP 工具设计指南

Self-ImprovementEvidence Lineage

Praxist：把“试过什么、为什么变好”沉淀成可追踪的 Solution Lineage

Praxist 把可复现实验产物、评测结果和已验证机制组织成 typed evidence graph，让后续 Agent 继承已经证明有效的机制，而不是反复重学。

启发：浏览器工程经验库应保存 Patch → Benchmark → 结果 → 条件 → 后续继承关系，而不是扁平 notes。

SecuritySkill Library

EVOMAL：Self-Evolving Agent 会出现“自己污染自己的 Skill 库”

Agent 参考已有 Skill 创建新 Skill 时，恶意 Skill 可以被模仿和复制，再进入共享库持续传播。

警告：自动生成的 Skill / Rule 必须带 provenance、静态/动态检查、可执行 eval，并默认不可信。

EVOMAL 论文

Harness RSIFrozen Model

VideoHarness-RSI：不改模型，只递归改 Harness

固定 VLM 和接口，只让外层 Agent 修改如何组织、检索、打包证据的可执行程序；每轮 propose → execute → evaluate → retain。

启发：浏览器 Self-Improvement 最安全的第一层仍然应该是 Harness。

VideoHarness-RSI 论文

浏览器技术

WebMCP 开始明确 Agent Tool 的“状态机”属性

Chrome 要求定义 initial state：用户当前位于哪个页面、Agent 已有什么上下文、有哪些权限和系统约束；复杂工作流通过 role-play 拆成多个 Tool。

工程价值：Browser Runtime 未来需要理解前置状态、权限、可恢复错误和 UI 状态同步。

Fail gracefully 成为 Agent Web 的一等设计原则

工具不应只返回泛化错误，而应返回足以让 Agent 恢复执行的上下文，例如先执行搜索，再过滤结果。

端侧 AI

端侧 Agent 的下一层瓶颈仍是 Harness

VideoHarness-RSI 再次说明模型冻结时，仅优化可执行上下文构造程序仍能得到收益。浏览器内模型尤其适合优化 DOM / AXTree / History 的选取和压缩。

端侧经验库默认应该“不信任”

Local Agent Skill 往往拥有文件、Shell、浏览器 Session 等更高权限，因此 provenance、版本、签名、sandbox 和 eval 应成为基础能力。

Browser Self-Improvement

WebMCP 本身开始出现轻量 Self-Improvement Loop

目标和状态 → role-play → Tool → Evals → 上线 → telemetry → 更新 Evals 和 Tool definitions。虽然优化的是网站 Tool，不是 Chromium 源码，但这是很现实的 Browser Capability Self-Improvement。

Praxist：经验应该有 Lineage，而不只是 Memory

每条 performance/debugging Skill 都应该能追溯到 Regression、Trace、Patch、Benchmark、设备/版本条件和最终结果。

EVOMAL：Learn 层必须加 Trust Gate

合理流程应是 Candidate Skill → provenance check → static scan → sandbox execution → regression eval → review/sign → trusted store。

VideoHarness-RSI：先限制可修改对象在 Harness

可以先允许 Agent 改采集脚本、Trace 查询、Pinpoint 调度、诊断 Skill、Benchmark 编排，而不允许改 Self-Improvement Protocol 和 Browser Security Boundary。

今天的一个判断

过去几天我们逐步补上了 Memory Hygiene、Executable Learning、Reviewable Improvement。今天应该再加一个：Trusted Learning。

Self-Improvement 不是让 Agent 学得越快越好，而是只有通过来源追踪、可执行验证和权限隔离的经验，才允许进入长期知识层。

Telemetry → Diagnose → Candidate Patch / Skill
          → Benchmark → Review → Trust Gate
          → Trusted Store → Canary → Revalidate / Decay
