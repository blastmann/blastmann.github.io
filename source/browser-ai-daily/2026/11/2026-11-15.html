1. WGSL Shader Print：为 WebGPU Shader 增加原生可观察的计算日志（11/13 提案，11/14 继续审查）

发生了什么：W3C GPU for the Web 工作组成员在 gpuweb #11101 提出 shader-print 草案，起草日期为 11 月 13 日（UTC），11 月 14 日仍有审查活动。提议 WGSL 支持 print 函数和类似 JavaScript 模板字符串的表达式插值，例如把 Shader 中的中间计算值输出到浏览器开发者控制台，而不是只能靠 CPU Readback 或 GPU 平台专用调试器间接检查。

技术新颖性：草案不仅定义打印语法，还描述浏览器可移植实现：编译器把日志操作改写为向内部 Storage Buffer 写入含格式 ID、Invocation 元数据和值的记录，使用原子操作预留空间，再由宿主 Readback 和格式化输出；同时比较 Metal shader logging、Vulkan DebugPrintf 与 HLSL 的原生能力。Dawn/Tint 已有相关原型，不是 WebGPU 标准已通过或 Chrome/Safari/Firefox 均已支持。

可验证证据与边界：PR 提供 134 行完整提案及技术路径，作者明确留下日志输出格式、回调方式、可否静默 no-op、功能开关及 CTS 测试的开放问题。没有给出稳定浏览器支持或性能成本。工程启发：Browser Agent 可以在定位 WGSL 推理 Kernel 错误时获取 GPU 内部数值证据，但需要独立控制日志采样、回读开销、敏感数据和超限行为。值得深入研究/实测：高（先跟踪规范和 Dawn 原型）。来源：工作组 PR 原文。

2. WebGPU Subgroup Matrix：FP8/BF16 被纳入矩阵扩展提案（11/10 合并，7 日补推）

发生了什么：gpuweb #11093 于 11 月 10 日合并到 Subgroup Matrix 提案，新增 bf16、f8<e4m3>、f8<e5m2> 三类有限用途的矩阵运算数据类型，并补充 Vulkan、D3D12、Metal 3/4 的原生类型映射和硬件能力条件。

技术新颖性：不是简单让 WGSL 全面支持 FP8 普通标量，而是让浏览器的 Subgroup Matrix/协作矩阵接口可描述低精度输入、特定输出精度和矩阵尺寸，从而让推理 Runtime 有机会直接调用硬件矩阵计算路径。Metal 4 的 matmul2d、Vulkan Cooperative Matrix、D3D12 Wave Matrix 对应能力不同，必须由适配器声明实际支持配置。

可验证证据与边界：提案代码已合并，但并不代表各浏览器已经实现此扩展，也不代表所有 GPU 都能硬件加速 FP8。尚缺跨 Safari/Chrome/Firefox 的 CTS、数值误差和端到端推理基准。工程启发：针对浏览器端小模型矩阵乘，评测应按 GPU 实际支持能力分层，比较原生低精度路径与现有 F16/F32 或 Shader 手写路径，并同时记录误差、加载时间和内存峰值。值得深入研究/实测：高（API 标准与硬件协同方向）。来源：已合并 PR、规范镜像提交。

3. Chrome UX Report：开始用 Soft Navigation 的 FCP 和导航类型观察 SPA 页面（11/11 发布，7 日补推）

发生了什么：Chrome 团队 11 月 11 日更新 2026 年 10 月的 CrUX 发布说明：实验性 Soft Navigation 指标新增 FCP 和 Navigation Types，并已进入 CrUX API 与 CrUX Vis，计划下个月进入 BigQuery。之前实验口径已包含 Soft Navigation 的 LCP/CLS/INP。

技术新颖性：传统一次导航只观察文档首次加载，而 SPA 内部点击切换内容通常没有完整 Document Navigation。将这种“软导航”纳入真实用户体验指标，意味着浏览器观测开始覆盖长期驻留单页应用的持续交互，而不仅是首屏。

可验证证据：Chrome 的 2026 年 10 月数据中，按其试算口径纳入 Soft Navigation 后，Core Web Vitals 达标站点比例由 56.3% 变为 60.3%。这是统计口径改变，不是网站实际性能提升了四个百分点；官方计划 2027 年 5 月再考虑纳入常规 Core Web Vitals。工程启发：浏览器性能采集、AI Agent 性能回归与 SPA 业务转化测量都应区分硬导航和软导航，并保留 Navigation ID 及前后台状态。值得研究/实测：高（尤其 Web 性能观测）。来源：Chrome CrUX 官方 Release Notes（11/11）。

浏览器技术

WGSL unrestricted_aliasing：PR #11100 提议解除大部分指针参数别名限制，同时在会影响 Uniformity 的情况下保留诊断。Dawn/Tint 于 11 月 13 日已经提交相关编译器支持。这是实现中的可选语言能力，不是标准完成或 Safari/Firefox 支持声明。它对编译器与复杂 WGSL 代码生成值得研究，但目前没有可信性能提升数据。

Chromium 遥测安全边界：11 月 13 日的GPU.WebGPU.Support 指标恢复提交解释了此前为什么在 Windows/Android/Linux 默认关闭枚举式探测：Windows 枚举 D3D12 适配器可能唤醒休眠独显并卡住 GPU 进程，Android/Linux 旧枚举路径可能崩溃。新实现优先检查正在使用的适配器，处理 EGLContext 恢复。这是重要的“遥测不能破坏被观测环境”工程风险，不属于新 GPU 算法。

其他引擎：本观察窗口未验证 WebKit/Safari、Firefox、Edge、Brave、Opera 具有同等重要且未被本周重复报道的架构首发；不填充常规版本修补。

端侧 AI

GPU 侧新信息以 FP8/BF16 Subgroup Matrix 为主。它将“浏览器内用 Shader 模拟矩阵算子”进一步推向“通过可移植 GPU API 描述不同硬件的矩阵指令”。这仍是规范提案层，想证明对端侧 AI 有意义，需要实测 M/N/K、Batch=1、Quantization 格式、显存、数值精度以及真实模型 Prefill/Decode，而不是只跑裸矩阵乘。

浏览器 × AI

Shader Print 有可能成为“Agent 调试 WebGPU Runtime”所缺失的观察工具：执行已知输入，收集 Shader 中间值，与 CPU Golden Reference 对照，再形成候选代码修改。但该自动化闭环只是可迁移的工程设计建议，目前没有证据表明工作组已发布一个能够自动修复 GPU Kernel 的 Browser Agent。

今天的一个判断

未来一代浏览器内 AI Runtime 的关键差异，不只是模型算得快，而是低精度矩阵计算能否对接硬件、计算内部能否被可靠观测，以及长时间驻留的 Web 应用能否被正确度量。本期三个机制分别补上这三个方向的一块拼图，但距离跨浏览器正式交付仍有明显差距。
