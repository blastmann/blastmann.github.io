浏览器 × 端侧 AI 日报

2026-08-23｜长任务 Browser Agent 可靠性、浏览器 AI Provider 编排、WebGPU 本地模型与 Browser Self-Improvement 起点。

今天最值得看

Browser Agent

Wuying-Browser-Agent / BrowserBench：长任务可靠性比单步能力更重要

这一方向把 Browser Agent 从单次 click/observe 推到长链路执行，强调结构化 observation/action/state、恢复训练与 Browser Harness 对可靠性的贡献。

判断：Browser Agent 的瓶颈正从“大模型会不会操作网页”转向“执行系统是否支持恢复、状态管理和轨迹复用”。
Firefox × AI

Firefox × Exa：浏览器开始承担 AI Provider 编排层

浏览器不再只是把 AI 功能硬编码到单一模型，而可能逐渐承担 provider selection、permission、context routing 和 capability orchestration。

启发：Browser Runtime 需要一层 AI Provider / Capability Router。
On-device AI

LFM2.5 2.6B + WebGPU：小模型进入浏览器 Agent 可用区间

2–3B 级模型持续逼近端侧可运行区间，WebGPU 推理让“本地理解 + 云端升级”更现实。

Browser Self-Improvement

第一阶段不该直接放开自动改 Chromium Core

更现实的路径是先让 AI 自动改善验证与诊断系统，再逐步进入候选 Patch、Benchmark、Canary 与经验沉淀。

浏览器技术

WebKit：Site Isolation / Wasm / IPC 继续强化运行时边界

这类改动长期影响 Browser Agent 的 capability boundary：Agent 将拥有更多浏览器内部能力，因此进程、origin、IPC 与权限隔离会越来越重要。

Firefox 两周发布节奏

更高频的稳定发布意味着 Agent / AI 功能未来也需要更快的 capability rollout、回滚与 telemetry 机制。

端侧 AI

LFM2.5-QAD 与 LFM2.5-VL-3B

小模型路线继续验证一个产品判断：Browser Agent 的低风险理解、摘要、分类、简单视觉判断，可以优先在本地完成；复杂规划再升级到云端。
