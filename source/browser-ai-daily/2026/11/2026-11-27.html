今天最值得看

1. MixMoMo：在手机上动态决定 MoE 专家的量化精度与执行设备

11 月 25 日 UTC 首次提交的 MixMoMo 研究以当前 token 的激活值和离线量化敏感度估计误差风险，而非单凭专家路由分数选择精度；再依据设备实际执行耗时，把不同精度的专家分配至 GPU 和 NPU 并行执行。NPU 端将可共享配置的反量化 tile 合并，用 Hexagon HVX 批量处理，减少准备开销。

作者扩展 llama.cpp 的 OpenCL 与 Hexagon HTP 后端，在 OnePlus 15（16GB RAM）和 OnePlus 13（24GB RAM）上测试。专家权重按需加载，并非全部常驻内存。

平均分别为 3.72× 和 1.53×；混合精度比较约束平均专家位宽为 4 bit。Qwen3-Next 的 GSM8K 准确率为 84.48%，FP16 为 84.53%。均为论文作者实验，不代表所有任务等精度，也没有独立复测。论文正文与实验。

技术新颖性：高；值得研究：非常高；成熟度：真机研究原型。与此前 MoMoVL 的模态感知量化不同，此处重点是按 token 估算量化风险、异构设备调度和向量反量化协同。未核实完整实现公开或上游合并。建议复测绝对 TPOT、TTFT、闪存 I/O、内存峰值、长时间温控和电量，而非仅看相对倍数。

2. llama.cpp OpenVINO：KV-only Prefill 跳过不必要的计算图

11 月 26 日的 PR #33088 提出对具有 KV 共享注意力的模型进行静态图裁剪：Prefill 只输出 KV Cache 写入结果，去掉仅用于 logits 的后段层及 LM Head；需要最终 logits 时，再用 Decode 图处理输出 token。另将大型 embedding table 的行查找放在 Host，避免 NPU 重复搬运整个表。

适用于特定 KV 共享图、每批至多一个输出 token 等条件；4 个 needle prompt 中有一个近似并列 token 与基线不同（基线自身亦有波动）。这不是通用无损加速证明。PR 仍开放，数据来自贡献者，未独立复测。

技术新颖性：中高；值得实测：高。区别于一般 kernel 加速，它直接按阶段输出依赖删除无用计算。可研究类似裁剪能否移植到其他静态推理后端，但需验证缓存状态、输出一致性和编译缓存失效。

端侧 AI

今天的一个判断

端侧推理优化越来越需要在每个计算阶段决定哪些工作真正必要、哪些设备最适合执行，而不是仅降低模型位宽。今天最值得研究 MixMoMo 的量化风险与异构调度，最值得尝试复现 KV-only Prefill 的正确性及延迟收益。两者均需独立验证。
