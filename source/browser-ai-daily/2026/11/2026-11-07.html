今天最值得看

1. Browser Harness：一次审查删除 55 个违反项目访问规则的站点 Skill（11 月 7 日已合并）

发生了什么：browser-use/browser-harness PR #976 于 11 月 7 日 07:47（北京时间）合并，删除 55 个站点专属 Skill，另调整 X、GitHub、NASA 的部分访问路径。作者于 11 月 6 日审查每个 Skill 对应站点的 robots.txt 或服务条款，并安排独立反驳式复核，重新获取来源后再判断；PR 总计涉及 63 个文件。触发条件包括针对具名 AI User-Agent 的禁止路径、明确禁止 AI/ML 自动化利用的条款。项目将一般反爬声明与其明确政策条件区分开来。

为什么重要：与此前新增 Skill 的报道相反，这次的“改进”是主动缩减不应使用的能力。这不是在宣称 robots.txt 本身等同法律，而是项目对自己工具执行范围实施一套明确政策，并保留变更证据。

工程启发：Browser Harness 除正确性、稳定性外还应具备持续的权限/站点规则复核；发现规则变化时自动降级或撤销 Skill，而不是让模型绕过限制。状态：已合并；实际运行站点覆盖率下降，长期重新验证尚未见证据。

2. WebGLLM：绕开 WebGPU 依赖，在 WebGL 2 中执行本地语言模型（11 月 6 日新仓库）

发生了什么：webgllm/webgllm 于 11 月 6 日 08:24（北京时间）创建，已公开 npm webgllm 0.1.x。它使用 WebGL 2 的浮点渲染目标、Worker 和 OffscreenCanvas 来运行 LFM3、LFM2.5、Qwen3.5，缓存模型于 Origin Private File System，对外提供兼容 OpenAI 的接口、流式输出、取消、工具调用和受约束 JSON。11 月 6 日发布的 0.1.3 还提供 onMemoryClaim 内存预算协调回调；0.1.5 修正 Schema 约束逻辑。

为什么重要：WebGPU 尚不可用或不稳定的移动浏览器上，WebGL 2 仍可能为小模型提供兼容性备选，尤其适合比较 Firefox Android 和旧版 iPhone 的实际情况。多模型内存管理接口也比一次性推理 Demo 更贴近真实产品。

工程启发：对端侧 AI Runtime 采用明确的 WebGPU → WebGL 2 → WASM/CPU 能力检测和降级策略。限制：这是 0.x 早期实现，作者文档中的支持范围未经过跨设备独立验证；不应把“支持 WebGL 2”直接等同于所有手机高性能可用。

3. OnlyRead：在网络请求层拒绝 Browser Agent 的写操作（11 月 5 日首发，7 日内补推）

发生了什么：onlyreadai/onlyread 11 月 5 日创建并发布 v1.0.0。其 Chromium MV3 扩展通过 Chrome Debugger API 观察和阻断请求，结合 HTTP 规则、站点专属解码器、缓存判定和可选 AI 审查，尝试让 Agent 在登录状态下“可以读、不能发帖/修改/删除”。不确定的写入请求采取拒绝策略。其第二级 AI 审查使用外部模型服务，只发送经过筛选的请求片段，并非完全离线。

为什么重要：这把安全约束从 Prompt 移到模型之外，直接影响 Browser Agent 权限体系与低风险阅读模式。工程启发：区分站点读取权限和具有副作用的网络/DOM 行为，并使用真正独立的执行约束。限制：基于网络请求的阻断不等于覆盖所有客户端状态修改、后台同步或其他扩展/进程渠道；项目自述的站点覆盖和安全效果尚未经独立审计。许可证 AGPL-3.0。

4. Qwen3-0.6B Inside Out：把完整模型层间激活展示在浏览器内（11 月 6 日新仓库）

发生了什么：davidheineman/qwen-web 11 月 6 日 11:48（北京时间）创建，手写 WGSL 完成 Qwen3-0.6B 的前向计算，展示每层注意力、MLP、残差流、Logit Lens 与权重矩阵，可逐 Token 观察中间结果。作者提供与 Python Transformers 参考实现的对照，报告残差/Logit 相对误差约 3e-6、注意力约 1e-6，并保留浏览器 E2E 自检。

为什么重要：不同于黑盒聊天 UI，它为 Browser AI Runtime 提供了面向数值正确性和算子调试的可观测入口。模型原始 BF16 权重约 1.19GB；为了保留完整注意力图，当前没有 KV Cache，最多 256 Token。

工程启发：跨 WebGPU Backend 做优化时可以把 Python Ground Truth、层间激活差异和浏览器端自检作为发布前验证。限制：早期可视化原型，非生产推理引擎；相关性能和误差为作者自述数据。交互 Demo。

5. ThisBash：普通网页会话可借 AI 远程控制跨越本机权限边界（11 月 4 日研究，7 日补推）

发生了什么：Forever Security 于 11 月 4 日发表 ThisBash 原始研究。研究者演示：有权控制 claude.ai 的浏览器扩展，利用 Claude Dispatch 在网页端可访问的接口，驱动已配对的 Claude Desktop 执行本机命令，甚至可能作用于同一账号下的另一台电脑。研究者在 2026 年 5 月已报告，Anthropic 当时确认为有效并以已知重复问题结束报告；研究方称 Dispatch 计划退役，但未在本期确认所有部署是否已经完全停用。

为什么重要：登录状态、账号身份与用户对本机操作的明确授权不能混为一谈。工程启发：远程 Browser/Agent Runtime 必须让执行命令和批准命令发生在不可被同一低权限页面或扩展同时控制的边界内；跨设备需要重新确认权限。限制：这是研究者在特定受控配置中的演示，不代表任何浏览器扩展都能直接利用。

端侧 AI

WebGLLM 和 Qwen-Web 代表两类不同任务：前者追求 WebGPU 不可用时的小模型可部署性，后者追求 WebGPU 计算可解释性及数值可证。对移动端建议用同一任务比较 WebGPU/WebGL 2/WASM 的首 Token、持续输出、模型加载、峰值内存、后台恢复和能耗，并区分开发者演示与完整设备测试。近期项目均尚无独立手机端 Benchmark。

浏览器 × AI

OnlyRead 将只读限制放在网络/策略层；Chrome DevTools MCP 候选补丁让 Cancel 真正到达页面工具；claude-do-it 则将多 Agent 任务放进共享且带版本号的 Markdown 文档。三者分别针对“允许做什么”“取消能否真正生效”“并发工作是否丢任务”。这些问题共同构成 AI Native Browser 的运行时边界。

今天的一个判断

浏览器 AI 能力的提升，并不总是增加工具或参数。能识别不该执行的操作、能真的取消正在运行的调用、能发现兼容性与数值错误，以及能撤销过期 Skill，都是更可靠的工程进步。对移动端与 Browser Runtime 团队，最值得立即试做的是“可撤销权限 + 可证实的操作回执 + 定期复验”的小范围集成。
