今天最值得看

1. Chromium WebMCP 工具接口变动：Playwright 需要兼容新旧 Schema（待合并）

发生了什么（10 月 23 日凌晨，北京时间）：Playwright PR #43578 报告 Chromium 的 WebMCP 工具 API 行为变化：部分工具 Schema 从原有形态变为 null，执行失败时的错误消息也有新旧两种格式。候选修复将 null Schema 规范化为原有 WebMCP 工具结构，同时接受两种错误格式。该 PR 截至本次调研仍为 Open。

为什么重要：WebMCP 使网页主动向 Agent 暴露工具，但浏览器版本升级可能悄悄改变 Agent 看到的工具描述与失败语义。工程启发：Browser Runtime 应按 Browser Revision 保存工具 Schema 指纹、工具执行结果和错误类型；每次 Chromium Roll 自动执行 WebMCP 契约测试，防止静默兼容性回归。Playwright 原始 PR

2. Chrome DevTools MCP：JavaScript 弹窗不再让导航工具一直等待（Hermes Agent 辅助，待合并）

发生了什么（10 月 22 日）：PR #3322 修复 alert/confirm 等未处理弹窗阻塞 new_page、navigate_page、前进/后退/刷新时，Agent 可能一直等待导航，或者错误地报告成功的问题。候选方案在弹窗出现时中断导航等待，保留弹窗状态，并提示使用 handle_dialog；同时避免第三方工具发现继续等待被弹窗阻塞的 Renderer。

验证证据：作者披露 Hermes Agent 辅助实现、测试和说明。Windows 11 + Chrome for Testing 上，定向回归测试 174 项通过；完整测试 1742 项通过、1 项失败、9 项跳过。唯一失败的 symlink 测试在未修改基线也可复现，不能表述为全套测试全部通过。PR 仍待人工审查。

工程启发：Agent 的工具调用应返回“导航中断原因、待处理 Dialog、可恢复操作”，而不是把弹窗等同于导航失败或成功。此案例已覆盖 Reproduce → Agent-assisted Patch → Targeted Verify，尚未完成 Review/Merge/Canary。原始 PR

3. llama.cpp：AI 辅助 CUDA Graph 缓存改进，Decode 提升 3.7%–5.2%（待合并）

发生了什么（10 月 23 日凌晨）：PR #31004 针对不同首节点形状反复触发 CUDA Graph 重建的问题，增加按 Graph Shape 区分的多图缓存，并采用有界容量和基于使用频率的淘汰策略。作者明确披露使用 AI 追踪问题、设计算法并辅助编码。

验证证据：Qwen3.8-27B Q4_K_M、DFlash2-7 Decode 场景下，GB300 由 122.244 提升至 126.801 tok/s（+3.728%，95% CI [+3.470%, +3.988%]）；RTX PRO 6000 Blackwell 由 146.681 提升至 154.355 tok/s（+5.230%，95% CI [+4.781%, +5.681%]）。普通 Decode 仅约 +0.15%。作者使用每设备每模式 8 对交替基线/候选的新进程测试，其他批处理基准未见变化。上述均为作者结果，PR 尚未合并。

工程启发：对 WebGPU/Dawn 的 Pipeline Cache、Shader Variant 和模型图缓存，Agent 应先根据真实 Trace 找到缓存抖动，再使用有界缓存、配对 Benchmark 和置信区间验证，避免为个别形状优化而造成长期内存膨胀。原始 PR

4. Browser Use：结构化 Done 可能把失败任务静默标记为成功（待合并）

发生了什么（10 月 22 日）：PR #6178 发现启用 output_model_schema 时，结构化完成动作从模型可见的 Schema 中隐藏 success 字段，却在解析时默认为 True。即使任务被阻断、返回空数据或 data.success=false，history.is_successful() 仍可能为 True。候选修复增加模型必须显式填写的 task_success，同时兼容旧 success 输入。

验证边界：作者没有在当前环境执行仓库测试，引用此前相关方案的本地测试；因此目前只能视为有明确根因和补丁的待验证修复。工程启发：Browser Agent 的完成回执应拆分模型声明、工具实际执行、页面后置状态和独立业务验证，任何一层缺失都不能默认成功。原始 PR

5. Chrome DevTools MCP：修复本地浏览器地址误判，恢复文件路径安全检查（已合并）

发生了什么（10 月 22 日）：PR #3321 修复以 0.0.0.0、[::] 等未指定地址连接本机 Chrome 时，被错误分类为远程浏览器的问题。这使 upload_file、install_pwa、install_extension 的本地路径校验被跳过。新实现专门识别本机浏览器 Endpoint，不改变页面 URL 的 localhost Telemetry 语义；增加了旧版本会失败的回归测试，并已合并。

为什么重要：Browser Runtime 的连接地址、页面来源和文件权限是三个不同概念。工程启发：对 Agent 的文件系统能力必须按实际浏览器执行位置和授权范围判断，不能复用面向网页 URL 的字符串判定。原始 PR

浏览器技术

Playwright Trace Viewer 的截图时间对齐（待合并）：PR #43579 修复 Screencast 帧的 Wall Time 乱序时，Trace Viewer 选不到真正时间最近帧的问题，候选方案选择全局最近帧并保留录制顺序和同距离时的稳定选择。对 Agent 调试来说，错误时间点的截图会误导故障归因。原始 PR

Chromium OOPIF 截图测试（待合并）：PR #43585 发现跨进程 iframe 尚未绘制就截图，CI 可能生成全白图；候选修复在截图前等待子 Frame 真正 Paint，而不修改基准图片。启发：视觉验证应等待可观测的绘制完成事件，而不是固定 sleep 或静态截图时间。原始 PR

端侧 AI

交互优先的 Prefill 调度（待合并）：llama.cpp PR #30992 提出 --prefill-budget-busy N：当已有用户正在接收 Decode 输出时，将新请求的长 Prefill 切为最多 N Token 的小段；等待队列优先处理较短请求，连续 8 次未获调度的请求提高优先级。默认关闭，并新增 /metrics 触发计数与自动化测试。作者在 Ryzen AI MAX+ 395 的共享内存平台上提出方案，披露 Claude/Qwen 辅助开发；尚无可外推的端侧性能数字。启发：端侧推理调度应同时衡量前台输入响应、Decode 流畅度、Prefill 吞吐和等待公平性。原始 PR

WebGPU 测试覆盖（待合并）：llama.cpp PR #30977 拟重新启用 WebGPU 的 Flash Attention 开启路径下的 test-llama-context；关闭 FA 的路径执行非常慢。启发：CI 不能仅因某后端测试慢就永久失去正确性覆盖，应记录特性开关、慢测试原因和替代覆盖。原始 PR

浏览器 × AI

确定性任务回放（已合并文档）：Browser Use PR #6183 补充 save_history() 与 load_and_rerun(variables=...) 的用法，说明稳定页面上的已记录动作可避免每一步调用 LLM，但提取与总结仍可能调用模型；页面变化时可能在已执行部分动作后抛错。作者报告本地表单验证：回放提交前 0 次模型调用，后续提取与总结 2 次。启发：高频浏览器任务可采用“Agent 探索 → 独立验证 → 参数化确定性回放”，但必须有页面漂移检测、幂等和失败回滚。原始 PR

DOM 遮挡判断（待合并）：Browser Use PR #6182 发现 dataclass 的 __post_init__ 返回 False 不会阻止对象构造，倒置坐标矩形因此进入 Paint Order 遮挡计算；宽高非正的元素也应跳过。作者提供修改前失败、修改后通过的 4 项测试。启发：端侧小模型基于 DOM 选元素时，输入几何数据必须先通过确定性校验。原始 PR
