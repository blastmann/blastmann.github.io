浏览器 × 端侧 AI 日报

2026-08-24｜Real Chrome + Local Agent、WebMCP Workbench 与 Browser Capability Layer。

今天最值得看

Local Chrome

Agent Browser Gateway：真实登录态 Chrome + 本地 Gateway

Chrome Extension 与 localhost gateway 组合，围绕 tab/origin 授权、read/write operation 和 audit log，让 Agent 操作用户真实浏览器，而不是远程云浏览器。

判断：“Real Chrome + Local Agent”开始形成独立产品类别。
WebMCP

WebMCP Workbench：网站直接向 Agent 暴露结构化工具

如果网站可以暴露稳定 machine-readable actions，Agent 就不必总是依赖 DOM 猜测和视觉点击。

建议优先级：Native Browser API → WebMCP / Site Tool → DOM / AXTree → Vision → Coordinate Click。
Capability

Browser Capability Layer 成为必要抽象

Agent 不应该长期持有泛化浏览器权限，而应按 Tab / Origin / Operation 授权。

WebGPU

ONNX Runtime WebGPU 工程能力继续增强

device-free compile-only session 与 Windows sandbox / DXGI 相关修复，继续降低浏览器和桌面端 GPU 推理集成成本。

浏览器 × AI

Agent 权限模型应该从 Browser Extension 权限升级为 Capability Token

Browser Agent
   │
Agent Orchestrator
   │
Agent Runtime
   │
Capability Layer
   ├─ Tab
   ├─ Origin
   ├─ Read / Write
   └─ Tool
   │
WebMCP / DOM / AXTree / Vision / DevTools
   │
Browser Runtime

Agent 的“能不能做”应该由 Browser Runtime 的 capability enforcement 决定，而不是仅由 Prompt 约束。

端侧 AI

Local Agent 与用户真实浏览器的结合变得更自然

浏览器本地 Agent 可以保留登录态、页面状态和本地隐私数据；云模型只在复杂规划时升级。

Browser Self-Improvement

Capability Layer 同样是 Self-Improvement 的安全边界

未来 Agent 即使自动改进 Skill / Workflow，也不应该自动扩大自己的 Tab、Origin 或写权限。

今天的一个判断

Browser Agent 正从“模型控制浏览器”转向“浏览器内部拥有 Agent Runtime”。

真正的客户端机会不是再做一个云端 browser-use，而是把 Context、Capability、Local Model、Audit、Recovery 做进真实浏览器。
