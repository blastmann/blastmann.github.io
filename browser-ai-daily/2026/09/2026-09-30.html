浏览器 × 端侧 AI 日报｜2026-09-30

今天最值得看

1. AgentBug-Smith：自动把真实 Harness Bug 变成可执行复现

AgentBug-Smith 面向 agentic system 的 harness bug，从开源 Agent 系统持续发现真实问题并自动构造 executable reproduction。作者报告，相比普通软件 bug reproduction 方法，不同 backbone 下复现成功率提高 10.67%–27.56%。

为什么值得关注：Browser Self-Improvement 从 Telemetry、Crash、用户反馈走向 Diagnose 之前，最缺的是稳定、版本化、能交给 bisect 与 Patch Agent 的复现。

工程启发：先把 Crash、Trace、WPT failure、real-site failure 转成 Reproduction Artifact，只有稳定 replay 的问题才自动进入 Pinpoint/bisect/Patch loop。

AgentBug-Smith 论文

2. Mixture of Self-Improving Branches：Self-Improvement 不必只有一条演化路线

这项工作把 Harness evolution 从单一路径改成多个 self-improving branches：每个 branch 根据成功案例与历史调整 development subset 和 proposal policy，最后由 router 在执行前选择 branch head。论文报告相对 Meta-Harness 在 Terminal-Bench 2.0 提升 11.6%，SWE-bench Lite 提升 3.8%。

为什么值得关注：浏览器的低端设备、桌面高性能、GPU backend、网络/媒体 workload 不一定共享同一最优策略。强行把所有经验合并成一个全局 Harness，容易制造 retention regression。

工程启发：维护 platform/workload-specific improvement branches，再由 runtime evidence 路由。

Mixture of Self-Improving Branches 论文

3. Learning Meta-Skills：Learn 可以学习“如何给 Agent 搭环境”

Meta-Skill 让 Builder 从 Target Agent 的执行反馈中学习“什么时候需要什么支持”，再用冻结的 meta-skill bank 为未见任务构造 harness。Harness-Bench 与 NewtonBench 上，完整 meta-skill bank 相比无 skill 构造宏平均提升 8.95 个百分点。

为什么值得关注：这比记住具体任务步骤更容易迁移到浏览器工程：学习什么时候需要 Trace、visual diff、GPU/WPT、Cloud Reasoner。

Learning Meta-Skills for Agent Harness Design

4. Firefox：AI 模型继续被定义成可替换能力，而不是 Browser Runtime 本身

Mozilla 9 月 30 日社区更新再次强调 Firefox 157 的 AI 控制，并回顾与 Mistral 的合作：Mistral Small 4 将作为 Smart Window Beta 的一个模型选项。

工程启发：Browser Runtime 应拥有模型选择、AI enable/disable、权限、session 与 UI surface；模型只是可替换的能力提供者。

Mozilla September community update

端侧 AI

端云协同不应该等同于绑定某一个模型。Browser Runtime 更适合提供统一 Model Capability Interface：local small model、localhost runtime 和 cloud provider 都只是 route target；session、permission、evidence 与 user preference 留在浏览器侧。

闭环位置：Observe → Reproduce → Diagnose。

迁移到 Chromium：Crash cluster、Perf Dashboard regression、WPT failure 和 real-site incompatibility 都先生成 reproduction package；Pinpoint 和 Patch Agent 只消费稳定 reproduction。失败的 reproduction attempt 也作为负证据保存。

开源与论文 / 工程实践

今天三项 Harness 工作可以串成一条链：AgentBug-Smith 自动生成可执行问题；Self-Improving Branches 避免所有经验挤进单一路径；Meta-Skills 把成功经验抽象成“如何构造执行环境”。这使 Learn 更接近浏览器工程规则，而不是任务记忆。

今天的一个判断

Browser Self-Improvement 真正开始自动化之前，最值得先解决的不是自动写 Patch，而是自动把线上异常变成稳定、版本化、可重放的失败案例。

Patch generation 已越来越容易；真正决定闭环质量的是 reproduction 是否可信。没有稳定 reproduction，bisect、benchmark、verification 和 Learn 都可能在优化噪声。下一步很值得单独建设 Regression Reproducer，把 Telemetry / Crash / WPT / 用户反馈统一转换成 Agent、Pinpoint 和 CI 都能消费的 Reproduction Artifact。
